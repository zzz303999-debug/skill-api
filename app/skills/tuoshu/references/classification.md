# 分类字典

托书文档分两层分类：**业务类型**（决定 `doc_type` 字段）和 **模板指纹**（可选，用于 `source.template_hint`）。

## Layer 1：业务类型（doc_type）

按文档标题和主要字段判断：

| doc_type | 标题关键词 | 特征字段 | 说明 |
|----------|-----------|---------|------|
| `PACKING_NOTICE` | 做箱通知书 / 做箱通知 / 装箱通知 / 装箱通知书 | 做箱工厂、做箱时间 | 通知工厂准备装箱 |
| `TRANSPORT_ORDER` | 运输委托书 / 货物配舱通知书 / 货 物 配 舱 通 知 书 | TO / FM、多柜明细 | 委托货代订舱和运输 |
| `TRUCKING_ORDER` | 派车托书 / 拖车托书 / 车队托书 / 车队装箱通知单 | 港区、进港时间、司机 | 委托车队拖车 |
| `BOOKING_NOTE` | 做箱委托单 / 做箱委托书 / 装柜托书 / 装箱委托单 / 内装箱委托书 | 起运港、目的港、船期 | 综合订舱委托 |
| `UNKNOWN` | 无法归类 | | 兜底 |

**判定优先级**：标题 > 首行 > 主要字段。若标题模糊（如"做箱通知"同时含派车信息），按主要字段偏重方判定。

**注意**：很多派车托书标题也叫"做箱通知书"，但内容是给车队看的。此时看是否含"港区"、"提箱"、"进港时间"等派车字段。

## 使用方式

1. LLM 读取转换后的 markdown 文本，第一步判定 `doc_type`
2. 若命中已知指纹，填 `source.template_hint`
3. 未命中不影响抽取，`template_hint` 输出 `null`

## 扩展新模板

发现某个新模板反复出现（如新签约的货代），在上表追加一行：

- template_hint：`{货代拼音}_{业务}` 命名，如 `zhonglian_packing`
- 指纹：3-5 个高度独特的关键短语
- 命中样本：具体文件名

**不要过度细分**：只有当某模板出现 3 次以上、且字段布局明显独特时才立条目。零星模板走 UNKNOWN + LLM 通用抽取即可。
