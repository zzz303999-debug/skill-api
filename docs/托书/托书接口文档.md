# 托书抽取 接口文档

> 文档版本：v1.3
> 最后更新：2026-08-31
> **v1.3 变更**：**§6 错误码表与代码对齐**（2026-08-31）——按代码实况补齐 `llm_error`/`llm_response_format_unsupported`（502）与 422 场景的 `bad_request`（缺 file 字段校验失败，统一外壳）；`postprocessor` 等处的 `code` 为 `review_issues[]` 复核问题码（进入 `data.result.review_issues`），不属于接口错误码。
> **v1.2 变更**：**单文件抽取接口统一响应外壳**（2026-08-31）——`/skills/tuoshu/extract` 全场景（成功/业务失败/请求错误）统一为 `{code, msg, data}` 结构（对齐账单导入 v2.2 口径）：成功 `code="200"`、`data` 内 `{skill, version, result, meta, content?}`（`result` 即原顶层 `data` 抽取结果，原 `body.data/meta/content` 相应改为 `body.data.result/meta/content`）；错误场景 `code` 为机器可读错误码、`msg` 为可直接展示的中文说明、`data` 为原 details。批量抽取（§3）与其他接口暂不改造，保持原结构。
> **v1.1 变更**：**多提单号拒绝**（2026-08-21 用户拍板）——原文存在 ≥2 个不同提单号（提单号/主提单号/主单号标签锚定，大小写去重）→ `mbl_no` 置空 + blocking `conflicting_mbl_no` 拒绝，`ready_for_order=false`；主单+分单并存、同一提单号重复出现不算多提单号（对齐舱单 v1.8「一文件一票」）。
> 适用范围：skill-api 服务（单据智能抽取服务）
> 事实基准：代码实况（app/skills/tuoshu/schema.py、app/main.py、app/orders/schema.py）；与代码冲突时以代码为准

## 1. 概述

本服务提供四个与托书单据相关的接口：

| 接口 | 用途 | 是否下单 |
|---|---|---|
| `POST /skills/tuoshu/extract` | 单据文件结构化抽取（核心） | 否 |
| `POST /skills/tuoshu/batch-extract` | 批量抽取（≤10 文件） | 否 |
| `POST /orders` | 自由文本抽取并下单 | 是 |
| `POST /orders/parse-document` | 附件转订单字段（解析不下单） | 否 |

## 2. 单据抽取（/skills/tuoshu/extract）

### 2.1 基本信息

| 项目 | 值 |
|---|---|
| 路径 | `POST /skills/tuoshu/extract` |
| 内容类型 | `multipart/form-data` |
| 参数 | `file`（必填，单文件） |
| 支持格式 | `.xlsx`/`.xlsm`/`.xls`/`.docx`/`.doc`/`.pdf`/`.jpg`/`.jpeg`/`.png`/`.bmp`/`.tiff`/`.tif`/`.gif`/`.webp` |
| 大小上限 | 20 MB |
| 鉴权 | 需要（Bearer Token 或 X-API-Key） |
| 限流档位 | heavy（60 秒内每 IP 10 次） |

### 2.2 响应结构

**统一响应外壳（v1.2 起，对齐账单导入口径）**：全场景（成功/业务失败/请求错误）均为：

```json
{
  "code": "200",
  "msg": "解析成功",
  "data": {
    "skill": "tuoshu",
    "version": "0.1.0",
    "result": { "..." },
    "meta": { "..." },
    "content": "原文 markdown 全文（溯源用）"
  }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 业务码：成功 `"200"`；错误场景为机器可读错误码（`bad_request`/`empty_file`/`convert_error` 等，见 §6） |
| `msg` | string | 业务信息：成功 `解析成功`；错误场景为可直接展示的中文说明 |
| `data` | object | 成功时为业务数据；错误场景为补充详情（原 details，无则 null） |
| `data.skill` / `data.version` | string | skill 名称 / 版本 |
| `data.result` | object | 抽取结果（即原顶层 `data`，TuoshuOutput 全集，见 2.3） |
| `data.meta` | object | 溯源信息（见 2.6） |
| `data.content` | string | 原文 markdown 全文（溯源用，仅抽取成功时返回） |

**v1.2 迁移说明**：原顶层 `data`/`meta`/`content` 分别迁移至 `data.result`/`data.meta`/`data.content`；错误结构由原 `{"error": {...}}` 迁移至统一外壳。

### 2.3 result 字段总览（TuoshuOutput，即原 data）

| 字段 | 类型 | 说明 |
|---|---|---|
| `doc_type` | enum | `PACKING_NOTICE`做箱通知 / `TRANSPORT_ORDER`运输委托书 / `TRUCKING_ORDER`派车托书 / `BOOKING_NOTE`订舱托书 / `UNKNOWN` |
| `internal_ref` | string\|null | 我司业务编号（对应订单 c_sn） |
| `customs_declaration_no` | string\|null | 报关单号（不是提单号） |
| `customer_ref` | string\|null | 客户编号（PO 号） |
| `mbl_no` | string\|null | 提单号：≥8 位，仅数字或字母数字 |
| `hbl_no` | string\|null | 子提单号：同提单号格式；不得回退用主提单号填充 |
| `vessel` / `voyage` | string\|null | 船名 / 航次 |
| `carrier` | string\|null | 船公司（原文明示值优先） |
| `pol` / `pod` | string\|null | 起运港 / 目的港 |
| `transit_port` | string\|null | 中转港（「见设备单」等待查描述逐字保留） |
| `terminal` | string\|null | 港区 |
| `etd` | string\|null | 船期（YYYY-MM-DD） |
| `si_cutoff` / `customs_cutoff` | string\|null | 截单时间 / 截关时间 |
| `loading_time` | string\|null | 做箱时间（YYYY-MM-DD 或 YYYY-MM-DDTHH:MM:SS） |
| `containers[]` | array | 货物信息（每柜一条），见 2.4 |
| `factory` | object\|null | 做箱工厂，见 2.4 |
| `customer` | string\|null | 客户：优先 FM 后的值，缺失时取明确客户栏或正文抬头公司 |
| `shipper_company` | string\|null | 托运人公司（正文明确发货人/托运人栏位；对应订单 c_title） |
| `shipper_agent` | string\|null | 委托公司（正文抬头或落款） |
| `recipient` | string\|null | 收件方（TO/致/ATTN） |
| `doc_date` | string\|null | 文档日期（DATE，YYYY-MM-DD） |
| `sender` | string\|null | 发货方（FROM） |
| `sender_contact` | string\|null | 发货联系人（FROM/FM 联系人栏） |
| `remark` | string\|null | 汇总备注 |
| `order_mapping` | object | 订单字段映射，见 2.4 |
| `review_issues[]` | array | 复核问题清单，见 2.5 |
| `ready_for_order` | bool | 无任何 blocking 问题才为 true |
| `source` | object | `{file, doc_format, template_hint, extracted_at}` |
| `raw_text_snippet` | string\|null | 原文前 200 字摘要 |

### 2.4 嵌套结构

**containers[]（ContainerItem）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string\|null | 原文箱型代码；标准短代码 20/25/40+两字母；HQ/HC/DV/GP 不得改写 |
| `qty` | int | 箱量（缺省 1） |
| `container_no` | string\|null | 箱号：4 大写字母+7 数字 |
| `seal_no` | string\|null | 封号：无空格 |
| `packages` | int\|null | 件数 |
| `packages_unit` | string\|null | 件数单位（CTNS/PKGS/CARTONS…） |
| `gross_weight_kg` | float\|null | 毛重（KG），最多 3 位小数 |
| `volume_cbm` | float\|null | 体积（CBM），最多 3 位小数 |
| `po_no` | string\|null | PO 号 |
| `mbl_no` | string\|null | 该柜提单号 |
| `remark` | string\|null | 柜级备注 |

**factory**：`{name, address（详细街道地址）, contact, phone}`

**order_mapping**：`{c_sn, mbl_no, hbl_no, c_title, factory_name, c_note}` —— 下单接口的确定性字段映射（c_title=托运人公司、c_note=PO 号+原文备注）

### 2.5 review_issues[]（人工复核问题）

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | string | 问题代码（白名单制，见设计文档 §6） |
| `field` | string | 涉及字段路径（如 `containers[0].type`、`factory.address`） |
| `message` | string | 中文说明 |
| `source_values` | string[] | 原文候选值 |
| `blocking` | bool | 是否阻断（阻断问题存在时 ready_for_order=false） |

常见阻断问题：`missing_mbl_no` / `missing_customer` / `missing_address` / `missing_container_type` / `missing_container_measurements` / `conflicting_container_data` / `conflicting_transit_port` / `conflicting_mbl_no` / `hbl_misclassified_as_mbl` / `invalid_container_no` / `carrier_by_mbl` / `carrier_by_vessel` / `deterministic_ai_conflict` / `ungrounded_text` / `mineru_failed` / `mineru_low_confidence` / `scanned_pdf_ocr_unverified` / `vision_only_unverified` 等。

**多提单号拒绝（v1.1）**：原文存在 ≥2 个不同提单号（提单号/主提单号/主单号标签锚定，大小写去重）→ `mbl_no` 置空并报阻断 `conflicting_mbl_no`（source_values 含全部候选，人工核对后处理）；主单+分单并存、同一提单号重复出现不算多提单号（对齐舱单 v1.8「一文件一票」）。

**影响面（v1.1）**：HBL/MBL 同标「提单号」的存量 SI 文档此前可 `ready_for_order=true` 出单，现在全部转人工（`ready_for_order=false`）——请调用方对存量文档补充人工复核流程或合并输出单值后重提。

常见非阻断提示：`vision_cross_check_skipped`（已跳过视觉交叉核验，建议抽检）、`etd_year_missing`（船期缺年份已置空）、`unknown_container_type`（非标箱型逐字保留）、`notice_remark_restored`（已从「请注意」列表恢复备注）。

### 2.6 meta 字段

| 字段 | 说明 |
|---|---|
| `model` / `usage` | LLM 模型与用量（仅提取成功时） |
| `parser` / `parser_fallback` | 解析引擎与是否回退（pdfplumber/local/mineru/vision） |
| `deterministic_template` / `template_fingerprint` | 确定性模板命中信息 |
| `page_routes` | PDF 页级路由明细（每页 parser/confidence/issues） |
| `coverage` | 转换覆盖度（complete/omissions/embedded_images_processed） |
| `source_sha256` / `content_sha256` | 文件哈希 / 转换后内容哈希 |
| `source_bytes` / `content_chars` | 文件字节数 / 转换内容字符数 |
| `detected_format` | 按内容识别的真实格式 |
| `conversion_status` | `converted` / `needs_review` |

## 4. 自由文本下单（/orders）

### 4.1 基本信息

| 项目 | 值 |
|---|---|
| 路径 | `POST /orders` |
| 内容类型 | `application/json` |
| 鉴权 | 需要 |
| 限流 | heavy（60 秒内 10 次） |

### 4.2 请求参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `content` | string | ✅ | 自由文本订单内容（只解析显式「字段：值」格式，不调 AI、不补全、不推断） |
| `roomId` | string | ✅ | 上游会话标识，原样回传 |
| `userId` | string | ✅ | 上游用户标识，透传给下游订单接口 |

### 4.3 核心规则

- 必填校验：提单号 + 托运人/公司名称，任一缺失返回 422 `order_not_ready`，不下单（自由文本只要求字段非空，不校验 8 位格式）
- 箱型箱量支持 `40HQ*3+2*20GP` 混写，同箱型数量累加
- 做箱时间自动拆分：完整日期归做箱日期（YYYY-MM-DD），时间描述归装箱时间
- 订单创建请求不自动重试（防重复下单）

### 4.4 响应结构

```json
{
  "roomId": "原样回传",
  "source_fields": {"提单号": "OOLU4044379500", "...": "原文标签与值（逐字保留）"},
  "extracted": {"order_num1": "...", "c_title": "...", "..."},
  "order_data": {"...": "下单接口实际请求数据"},
  "upstream": {"code": 200, "msg": "添加成功", "data": "下游接口响应"},
  "meta": {"...": "元信息"}
}
```

## 5. 附件转订单字段（/orders/parse-document）

### 5.1 基本信息

| 项目 | 值 |
|---|---|
| 路径 | `POST /orders/parse-document` |
| 内容类型 | `multipart/form-data` |
| 参数 | `file`（必填） |
| 语义 | 解析不下单；调用方确认后自行提交 |

### 5.2 响应结构

```json
{
  "file": "上传文件名",
  "extracted": {"order_num1": "...", "c_title": "...", "factory_name": "...", "...": "OrderDocumentExtraction 全集"},
  "order_data": {"...": "组装好的下单数据（对齐 /orders 的 order_data 结构）"},
  "needs_manual_confirmation": true,
  "missing_fields": ["order_num1", "box"],
  "missing_reasons": {"order_num1": "原文未找到，请人工确认", "box": "格式不合法"},
  "meta": {"..."}
}
```

### 5.3 必填字段与缺失处理

必填：提单号、箱型、客户、地址、做箱日期、件数、毛重、体积。

- 字段缺失**不报错**（200 + needs_manual_confirmation=true）；每个缺失字段标注原因：`原文未找到，请人工确认` / `格式不合法`
- `order_data` 始终组装并返回（缺字段时缺失项为 null，driver 为 [{}]），由调用方人工确认后补充提交
- 全部字段齐备时 `needs_manual_confirmation=false`

**字段语义（OrderDocumentExtraction 关键项）**：

| 字段 | 说明 |
|---|---|
| `order_num1` | 提单号：纯数字或字母数字且 ≥8 位 |
| `c_title` | 客户：取 FM 后的值或抬头公司 |
| `factory_name` / `factory_bei` | 门点简称 / 详细街道地址 |
| `b_end_port` / `b_end_dock` | **中转港 / 目的港**（注意与自由文本语义对齐；「见设备单」等待查描述逐字保留） |
| `b_date` / `b_date_time_start` | 做箱日期（YYYY-MM-DD）/ 装箱时间描述 |
| `packages` / `gross_weight` / `volume` | 件数（+CTNS）/ 毛重（+KGS）/ 体积（+CBM），保留 2-3 位小数 |
| `data[]` | 货物明细行（一票多客户/多提单号时每行一条），无任何可输出行时为 null |
| `box[]` | 箱型箱量（4 位箱型） |

## 6. 错误码约定

**单文件抽取（/skills/tuoshu/extract，v1.2 起）**：错误响应套统一外壳（HTTP 状态码不变）：

```json
{
  "code": "错误码（英文 snake_case，机器可读）",
  "msg": "中文说明（可直接展示给用户）",
  "data": { }
}
```

**其余接口（批量抽取/自由文本下单/附件转订单字段）**：保持原 `error` 结构：

```json
{
  "error": {
    "code": "错误码（英文 snake_case，机器可读）",
    "message": "技术性英文说明（定位用）",
    "description": "中文说明（可直接展示给用户）",
    "details": { }
  }
}
```

| HTTP | 错误码 | 触发场景 | 中文说明 |
|---|---|---|---|
| 401 | `unauthorized` | 凭证缺失/错误 | 未授权访问，请提供有效访问凭证 |
| 400 | `bad_request` | 扩展名不支持、缺 file 字段校验失败（422） | 请求参数或上传内容不合法 |
| 400 | `file_too_large` | 单文件超过 20 MB | 上传文件超过大小限制 |
| 400 | `empty_file` | 空文件 | 上传文件为空 |
| 400 | `file_format_mismatch` | 扩展名与内容不符 | 附件格式不匹配，请上传正确的文档格式（PDF/Word/图片） |
| 400 | `unsupported_image_content` | 图片内容非受支持栅格格式 | 图片内容不是支持的格式 |
| 413 | `payload_too_large` | 请求体超限（不进 handler） | 请求体超过大小限制 |
| 422 | `convert_error` | 转换失败/损坏/无 extractable text | 附件解析失败，文件可能已损坏或格式不受支持，请联系人工客服 |
| 422 | `pdf_page_limit_exceeded` | 扫描 PDF 页数超限 | PDF 页数超过单次处理上限，请拆分后重试 |
| 422 | `vision_image_too_large` | 图片/渲染页超 vision 上限且无 OCR 文本 | 图片超过 vision 直传上限且无 OCR 文本可用 |
| 422 | `empty_converted_content` | 转换后无有效内容 | 文档转换后无有效内容 |
| 422 | `vision_disabled_no_ocr` | 无视觉能力且无 OCR 文本 | 当前模型无视觉能力且无 OCR 文本可用 |
| 422 | `order_not_ready` | 自由文本缺提单号/公司名（/orders） | 订单必填信息不完整，无法下单 |
| 429 | `rate_limited` | 触发限流 | 请求过于频繁，已被限流 |
| 502 | `llm_network` | LLM 网关网络故障（超时/断连） | 无法连接 LLM 网关 |
| 502 | `llm_upstream` | LLM 网关拒绝请求（限流/参数问题） | LLM 网关拒绝了请求 |
| 502 | `llm_response_format_unsupported` | 网关不支持结构化输出（自动降级重试后仍失败） | LLM 网关不支持结构化输出 |
| 502 | `llm_error` | LLM 调用未预期异常/响应无内容 | LLM 调用失败 |
| 502 | `parse_error` | LLM 未返回有效 JSON/结构不匹配 | 内容解析失败 |
| 502 | `order_upstream_error` | 订单上游拒绝/不可达（/orders） | 订单系统拒绝了请求或不可达 |
| 503 | `server_busy` | 并发满排队超时（10 秒） | 服务繁忙，请稍后重试 |
| 500 | `internal_error` | 服务内部错误（未包装异常兜底） | 服务内部错误 |

> 说明：`postprocessor`/`skill.py` 中 `review_issues[]` 项的 `code`（如 `missing_mbl_no`、`customer_cross_chain`、`mineru_failed` 等，见 §2.5）是**复核问题码**，出现在 `data.result.review_issues` 内，不属于接口错误码。
