## 2. 背景与目标

### 2.1 背景

货代/物流业务中，托书、做箱通知、运输委托书等单据每天大量产生，人工录入订单信息耗时且易错。单据格式多样：不同货代有不同模板（已积累 12 种常见模板）、不同文件格式（Word/Excel/PDF/图片/扫描件）。

### 2.2 目标

- 把"看单据 → 提取关键字段 → 录入订单系统"的过程自动化
- 输出**结构化、强类型、可校验**的数据，业务系统可直接消费
- 关键数字（提单号、箱号、件数、毛重等）**宁可让人工复核，不可静默出错**

### 2.3 核心设计原则

1. **零静默错误**：任何解析降级、数据冲突、来源可疑，都必须显式标记并要求人工复核
2. **原文保真**：编号类字段（提单号、箱号、封号、人名）逐字复制，不"智能改写"——一个字符错误（O vs 0、I vs 1）就是业务事故
3. **数字不计算**：件数/毛重/体积只做格式清洗，不做求和、不做单位换算
4. **来源可溯**：每个输出结果可追溯到原始文件、解析方式和时间

## 3. 名词解释

| 术语 | 说明 |
|---|---|
| 托书 | 海运托运委托书类单据统称，含做箱通知、运输委托书、派车托书等 |
| 提单号 | 主提单号（MBL）/子提单号（HBL），≥8 位数字或字母数字；**关单号即提单号**，报关单号不是 |
| 做箱时间 | 工厂装箱的日期/时间；**截单时间、截关时间不是做箱时间** |
| 中转港 vs 目的港 | 中转港是转运港口，目的港是最终卸货港，两者不得混淆 |
| 人工复核 | 系统无法高置信确认时，由人工审核确认的流程（review_issues 机制） |
| blocking 问题 | 阻断型复核问题，存在时必须人工确认后才能下单 |
| 模板指纹 | 识别出的已知客户/货代单据格式标记，用于提升抽取准确性 |
| MinerU | 文档解析引擎，负责低质量 PDF 页与图片的 OCR 结构化解析 |

## 4. 产品定位与使用场景

### 4.1 定位

面向业务系统的"单据信息结构化抽取"能力中台，一次部署承载多种单据抽取能力，每种能力有独立、精确的输入输出契约（见 OpenAPI 文档）。

### 4.2 典型使用场景

1. **托书自动录入**：业务系统收到客户发来的托书文件，调用抽取接口得到结构化数据，自动填入订单表单
2. **聊天文本下单**：客户在 IM 中发送订舱信息文本，业务系统调用自由文本接口直接生成订单
3. **附件预解析**：上传做箱通知附件，先解析出订单字段，人工确认补充后提交下单
4. **审计追溯**：通过内置日志页面查询每次请求的完整记录（上传了什么、结果如何、错误码是什么）

## 5. 功能架构总览

```
业务系统
  │ ① 上传单据文件（托书/做箱通知…）
  │ ② 传入自由文本（订单内容）
  │ ③ 上传附件转订单字段
  ▼
单据抽取服务
  ├── 文件识别（按内容而非扩展名判断真实格式）
  ├── 内容解析（Word/Excel 本地解析；PDF 按页分流；图片/扫描件 OCR）
  ├── 模板识别（命中已知模板用对应样例）
  ├── 智能抽取（LLM 结构化输出）
  ├── 校验修复（格式归一、来源核对、冲突检测）
  └── 结果输出（结构化数据 + 人工复核问题清单）
  ▼
业务系统（订单系统）—— 可安全自动下单 / 或转人工确认后下单
```

## 6. 功能需求

### 6.1 单据信息抽取（核心功能）

**输入**：上传单据文件（单文件）

**输出**：结构化 JSON，包含完整单据字段 + 人工复核问题清单 + 溯源元信息

**支持的文件格式**：

| 类别 | 格式 |
|---|---|
| Excel | .xlsx / .xls / .xlsm |
| Word | .docx / .doc |
| PDF | .pdf（文本型 / 扫描型） |
| 图片 | .jpg / .jpeg / .png / .bmp / .tiff / .tif / .gif / .webp |

**文件真实性校验**：按文件内容（而非扩展名）识别真实格式；扩展名与内容不符、空文件、非受支持图片内容均拒绝处理并给出中文错误说明。

**抽取结果包含的字段**（按业务分组）：

**单据信息**
- 文档类型：做箱通知 / 运输委托书 / 派车托书 / 订舱托书 / 未知
- 我司业务编号、报关单号、客户编号（PO 号）
- 主提单号、子提单号
- 文档日期、收件方、发货方、发货联系人

**运输信息**
- 船名、航次、船公司
- 起运港、目的港、中转港、港区
- 船期（开航时间）、截单时间、截关时间、做箱时间

**货物信息（每柜一条）**
- 箱型（如 40HQ，20/25/40 + 两位字母，原文怎么写就怎么保留，HQ/HC 不得互换）
- 箱量、箱号、铅封号
- 件数（+单位）、毛重（KG）、体积（CBM）、PO 号、柜级备注

**做箱工厂**
- 工厂名称、详细街道地址、联系人、电话

**业务主体**
- 客户（优先取 FM/FROM 后的公司名，其次客户栏/抬头公司）
- 托运人公司（对应订单的客户字段）
- 委托公司、汇总备注

**元信息**
- 原始文件名、文档格式、命中的模板、抽取时间、原文前 200 字摘要（溯源）

**批量抽取**：一次上传最多 10 个文件，逐文件返回结果或错误；单个文件失败不影响其他文件。

### 6.2 人工复核机制（重点）

系统对每份单据输出一个**复核问题清单**，每项包含：问题类型、涉及字段、中文说明、原文候选值、**是否阻断**。

#### 阻断型问题（必须人工确认后才能下单）

| 类型 | 说明 | 触发场景 |
|---|---|---|
| 必填缺失 | 缺提单号 / 缺客户 / 缺做箱地址 / 缺箱型 / 缺做箱日期 / 柜件数和体积同时为空 | 原文没有或无法提取 |
| 数据冲突 | 同柜存在多组件数/毛重/体积；承运人与提单号前缀冲突；中转港同时出现具体值和"见设备单" | 原文自身矛盾 |
| 来源可疑 | 托运人公司不是正文明确栏位；承运人由提单号前缀/船名推断而非原文明示；子提单号误填为主提单号 | 系统推断/修正后必须确认 |
| 保真校验 | 人名、编号未在原文逐字出现；箱号/封号格式非法（箱号必须 4 字母+7 数字） | 防 OCR/LLM 捏造 |
| 解析降级 | 扫描件仅 OCR 无独立文本层可核对；解析引擎低置信；图片超限跳过视觉核验；模板锁定值与 AI 结果冲突 | 任何降级路径 |
| 格式非法 | 提单号不足 8 位或含非法字符；日期格式/日历日期无效；件数毛重体积非正数 | 归一化清洗 |

#### 非阻断提示

如"已跳过视觉交叉核验（解析引擎高置信），建议抽检关键编号与数值"、船期缺年份已保留为空等。非阻断问题不阻止下单，但建议业务侧抽检。

#### 下单就绪标记

无任何阻断问题 → `ready_for_order=true`，业务系统可自动下单；否则必须人工确认。

### 6.3 字段抽取规则（业务规则详述）

| 字段 | 来源标签/版面 | 格式要求 | 缺失处理 |
|---|---|---|---|
| 主提单号 | 提单号/主提单号/主单号/关单号（**关单号即提单号**） | ≥8 位，仅数字或字母数字；不得含空格连字符；**报关单号、运编号、业务编号不是提单号** | 尝试按标签/格式特征恢复，仍无则复核 |
| 子提单号 | 子提单号/分提单号/HBL NO | 同提单号格式；**不得回退用主提单号填充** | 复核 |
| 客户 | FM/FROM 后的公司名（排除抬头货代、收件方）；或"客户/客户简称"栏；或正文抬头公司 | 只取公司名，剔除同行联系人/电话；文件名前缀**不是**客户来源 | 复核 |
| 做箱日期/时间 | 做箱/装箱日期、做箱/装箱时间 | 日期 YYYY-MM-DD；**截单/截关时间不是做箱时间**；时间描述（早上8点）单独存放 | 复核 |
| 船期 | 开航/开船时间/ETD（**开港时间不是船期**，归备注） | YYYY-MM-DD；原文只有月日时按文档日期/文件名年份推断，无法推断则复核 | 复核 |
| 中转港 | 中转港/中转港代码/TRANSSHIPMENT PORT | "见设备单"等待查描述**逐字保留**（表示存在中转港信息需查其他文件），不是没有 | 原文真正缺失才是空 |
| 目的港 | 目的港/卸货港/PORT OF DISCHARGE | 最终卸货港，**禁止用中转港冒充**；"见设备单"等占位描述不得作为目的港 | 复核 |
| 件数/毛重/体积 | 表格行/明细 | 只清洗单位千分位（"19,784 KGS"→19784）；毛重体积保留 2-3 位小数；**不做求和**；单位仅原文明确以吨（T）计时换算为 KG 并在备注说明，其余**不做换算**；≤0 视为无效 | 复核 |
| 箱型箱量 | 如 3*40HQ、40HQ*2、1x20GP+1x40HQ | 4 位（20/25/40+两位字母）；同箱型多行**数量必须累加**；HQ/HC/DV/GP 不得互换；非标准箱型逐字保留并提示 | 复核 |
| 箱号/封号 | 原文 | 箱号：4 大写字母+7 数字；封号：无空格；未在原文逐字出现则清空 | 复核 |
| 船公司 | 原文明示值优先 | 缺失时可按提单号前缀/船名推断，但**必须标记复核** | 复核 |
| 做箱地址 | 详细街道地址 | 保留省市区县/道路/门牌/园区，**并入原文现场联系人及电话**；不得把公司名混入地址 | 复核 |
| 货物明细行 | 表格数据行 | 一票多柜多行 → 每行一条；某行件数/毛重/体积不全时跳过该行 | — |

**空值约定**：缺失→null；原文"/"、"无"、"见附件"等占位符→null；数字缺失→null（不用 0）。

### 6.4 自由文本订单抽取与下单

**场景**：业务系统直接传一段自由文本（如 IM 对话里的订舱信息），服务提取字段并**调用下游下单接口**。

**输入**：

| 参数 | 说明 |
|---|---|
| content | 自由文本订单内容（必填） |
| roomId | 上游会话/房间标识，原样回传（必填） |
| userId | 上游用户标识，透传给下游订单接口（必填） |

**核心规则**：
- 只解析显式的"字段：值"格式，**不调用 AI、不补全、不推断**
- 支持的标签：提单号、托运人/公司名称、联系人、联系电话、船名、航次、船公司、门点简称/工厂名称、门点地址、装箱备注、启运港、中转港、目的港、港区、开航时间、内部编号、备注、件数、毛重、体积、货名、唛头、做箱时间、箱型箱量、船名航次
- 箱型箱量支持两种写法混用（`40HQ*3+2*20GP`），同箱型数量累加，非法数量忽略
- 做箱时间自动拆分：完整日期归"做箱日期"（YYYY-MM-DD），时间描述（早上8点/9:00）归"装箱时间"
- **必填校验**：提单号 + 托运人/公司名称，任一缺失返回 422，不下单（注：8 位以上格式校验属于附件解析与托书抽取的规则，自由文本只要求字段非空）
- 订单创建请求**不自动重试**（防止重复下单），调用方在结果不明确时也不应盲目重试

**响应包含**：roomId（原样回传）、原文标签与值（逐字保留）、抽取结果、下单接口实际请求数据、下游接口响应、元信息。

### 6.5 附件文档转订单字段（解析不下单）

**场景**：上传托书/做箱通知等附件，转换成下单接口字段，**但不下单**，由业务系统确认后提交。

**输出**：完整抽取字段 + 下单字段数据 + 必填字段缺失清单 + 每条缺失原因 + 是否需人工确认 + 元信息

**必填字段**：提单号、箱型、客户、地址、做箱日期、件数、毛重、体积

**缺失处理**（软校验）：
- 字段缺失**不报错**，返回 200 + 人工确认标记
- 每个缺失字段标注原因：`原文未找到，请人工确认` / `格式不合法`
- 缺失项保持空值返回，由人工补充后提交

**内置修正规则**（对 AI 输出做兜底纠错）：
- 客户只认原文真实来源：FM/FROM 后的公司名（排除抬头货代、收件方）、明确客户栏、抬头公司；原文无来源则置空
- 中转港/目的港互不混淆，按原文标签修正
- 关单号优先于运编号作为提单号
- 截单时间不得作为做箱时间

### 6.6 文档分类与模板识别

**文档类型**（四类+兜底）：

| 类型 | 标题关键词 | 典型用途 |
|---|---|---|
| 做箱通知 | 做箱通知书/做箱通知/装箱通知 | 通知工厂准备装箱 |
| 运输委托书 | 运输委托书/货物配舱通知书 | 委托货代订舱运输 |
| 派车托书 | 派车托书/拖车托书/车队装箱通知单 | 委托车队拖车 |
| 订舱托书 | 做箱委托单/装柜托书/配舱通知 | 综合订舱委托 |
| 未知 | 无法归类 | 兜底 |

> 注意：很多派车托书标题也叫"做箱通知书"，但内容是给车队看的——此时看是否含"港区""进港时间"等派车字段判定。

**模板识别**：已积累 12 个客户/货代模板指纹（如"喜临门装箱工厂+浙江经茂"、"倍联+赛格威做箱通知"、"ESFF 编号+做箱通知书"等）。命中模板后使用对应样例提升准确率；未命中不影响抽取。模板识别只是标注，不参与字段判定。

**扩展新模板**：新模板出现 3 次以上且布局明显独特时，登记模板指纹与样例即可（不涉及程序改动）；零星模板走通用抽取。

### 6.7 访问日志与审计

**查看页面**（浏览器直接访问 `/logs`）：
- 表格展示每条请求：时间、来源 IP、方法、路径、上传文件名与大小、耗时、状态码、错误码、请求 ID
- 点击可展开查看**完整请求体 JSON**（截断会标注）
- 支持按 IP/文件名/路径/状态码筛选、10 秒自动刷新、分页

**数据接口**（`/api/logs`）：返回 JSON（最新在前），支持分页与筛选，每条含客户端 IP、UA、请求体、响应体、文件大小、状态、错误码、耗时。

**审计要点**：
- 支持调用方透传请求 ID 关联全链路
- 云部署场景自动识别真实客户端 IP（信任反向代理头，客户端伪造的前缀被忽略）
- 日志落盘持久化，服务重启后仍可查历史；文件超 64MB 自动轮转；保留时长可配置（审计场景建议 30 天）
- **日志查看页面本身免鉴权，但日志数据接口必须鉴权**（含敏感信息）

### 6.8 健康检查与依赖探测

- 健康检查接口：返回服务状态（进程存活即 200）+ 已注册能力列表 + 三个依赖的状态探测：
  - AI 服务：配置与网络可达性（探测不发起真实推理，避免计费）
  - 文档解析引擎：启用状态与可达性
  - 订单接口：配置检查（**不实际探测**，因为探测即下单）
- 依赖不可达**不影响 200**：进程存活判定与依赖可用性判定分离，避免网络抖动误杀容器

## 7. 非功能需求

### 7.1 性能与容量

| 项 | 默认值 | 说明 |
|---|---|---|
| 单文件大小上限 | 20 MB | 超限返回错误，不截断处理 |
| 批量文件数上限 | 10 个/批 | 超限报错 |
| 并发任务数 | 4（可配 1-64） | 同时处理的文件数；满负荷时新请求排队，**排队超 10 秒返回"服务繁忙"（503）** |
| 扫描 PDF 页数上限 | 10 页 | 超过直接报错提示拆分，**绝不截断处理** |
| AI 单次调用超时 | 180 秒 | 失败自动重试 2 次 |
| 图片直传 AI 视觉核验上限 | 8 MB | 超限时降级为纯 OCR 文本并**强制人工复核** |
| 单文件处理时长 | 秒级~分钟级 | 取决于文件复杂度和 AI 响应；批量接口逐文件返回 |

### 7.2 安全

- **接口鉴权**：Bearer Token 或 X-API-Key 两种方式（可配置，生产必须开启；未配置仅限可信内网）
- 鉴权豁免仅限：健康检查、接口文档、能力列表、日志页面（页面无数据）；**日志数据接口必须鉴权**
- 防时序攻击：凭证比对为恒定时间比较
- 错误信息不泄露内部实现（网关地址、堆栈等）；批量接口单文件失败只返回结构化错误码
- 日志记录请求体含业务数据（PII），访问需鉴权

### 7.3 限流（防滥用）

- 按客户端 IP 滑动窗口计数（单进程部署下精确）
- 两档限流：
  - **重档**（单据抽取、订单接口）：默认 60 秒内 10 次
  - **轻档**（日志查询）：默认 60 秒内 120 次
- 被限流请求返回 429 + 等待秒数提示；支持内网 IP 白名单豁免
- 被限流的请求**仍会写入访问日志**，审计留痕完整

### 7.4 可用性与部署

- 容器化部署：API 服务 + 文档解析引擎（独立容器）两个服务
- 自动健康检查 + 失败自动重启；部署脚本支持拉码、构建、健康检查、回滚
- 生产可选三种方式：镜像部署 / 源码构建 / uv+systemd
- 建议 nginx 反向代理 + HTTPS；文档解析引擎只暴露内网

### 7.5 可扩展性

- **新增一种单据抽取能力（新 skill）三步即可**：新建目录 → 定义输出字段契约 + 抽取逻辑 → 重启服务自动挂载新接口，**无需修改任何全局代码**
- 业务知识库（船公司、港口、字段别名、箱型标准、模板样例）以文档形式集中维护，更新即生效
- 当前同步接口，后续可平滑演进为异步任务队列

## 9. 运营配置项

| 配置 | 说明 | 默认 |
|---|---|---|
| API 监听地址/端口 | 需监听 0.0.0.0 以支持局域网访问 | 0.0.0.0:9000 |
| AI 服务地址/密钥/模型 | 对接的 AI 服务 | 部署必填 |
| 思考模式开关 | 关闭可大幅降低响应耗时与成本（模型不支持自动降级） | 关闭 |
| 文档解析引擎开关/地址 | 启用后接管低质量 PDF 页与图片 | 部署环境开启 |
| 文档解析引擎失败回退 | 失败时回退到原有解析流程 | 开启 |
| 订单接口地址/超时 | 下游下单接口 | 30 秒 |
| 上传限制/并发数 | 见 7.1 | 20MB / 4 |
| 日志记录开关 | 请求体/响应体记录、截断长度 | 开启 |
| 日志保留时长 | 审计场景建议 30 天 | 24 小时 |
| 限流开关/档位/白名单 | 生产建议开启 | 关闭（本地） |

## 10. 质量保障

- **黄金用例回归**：内置 4 份真实业务单据（Word 1 份、PDF 2 份、图片 1 份，覆盖文本型 PDF、扫描型 PDF、图片 OCR 与本地转换各解析路径）+ 期望输出，回归测试保障抽取质量不退化
- 单元测试覆盖：字段归一化、箱型解析、订单文本抽取、校验规则、错误处理、限流、日志等
- 质量分级：解析引擎输出有"高/低置信"分级，低置信自动转人工复核

## 11. 已知限制与后续规划

### 11.1 当前限制

- 自由文本抽取仅支持显式"标签：值"格式，不支持无标签的纯文本段落推断
- 限流为单进程内存计数，多实例部署需引入共享存储
- 单文件同步处理，超大批量需拆分
- 目前仅内置托书一种单据抽取能力（架构支持快速扩展其他单据类型）

### 11.2 后续规划

- 异步任务队列（长批次、多阶段任务）
- 指标监控（/metrics）
- 更多单据类型（如运价表）接入
- 抽取结果持久化（对象存储）
- 人工复核工作台页面（当前系统只输出复核问题清单，复核操作由业务系统完成）
