# 托书抽取 设计文档

> 范围：托书抽取 skill（tuoshu）的解析链路架构、模块职责、确定性规则与人工复核机制。
> 事实基准：代码实况（app/skills/tuoshu/，2026-08-17）；与代码冲突时以代码为准。

---

## 1. 总体架构

```
上传文件（bytes + filename）
  │
  ▼
① 格式校验（skill.run）
  ├─ 扩展名白名单（accepts 14 种）→ 不支持 400 bad_request
  ├─ 内容格式识别（magic bytes，不信任扩展名）
  └─ 大小/空文件校验（20 MB / empty_file）
  │
  ▼
② 文档转换（convert_service.convert_to_markdown / convert_image_to_parse_result）
  ├─ Word/Excel → 本地确定性转换器（docx/xls/xlsx/word_xml/doc）
  ├─ PDF → 页级质量探测路由（合格页 pdfplumber / 不合格页 MinerU OCR 并行）
  └─ 图片 → MinerU 原图 OCR（高置信可跳过 vision；失败/低置信回退 vision）
  │   输出：markdown + ParseResult（parser/confidence/issues/coverage/vision_images）
  ▼
③ 确定性模板映射（deterministic_mapper.map_template）
  └─ 2 个精确模板：neizhuang_booking / bingsheng_transport（表头序列指纹 sha256）
  │   命中 → 锁定字段值 + 哨兵校验；冲突/异常 → blocking issue
  ▼
④ 零成本路由（prompt.detect_prompt_route）
  └─ 12 个模板 marker + 标题/操作字段规则 → doc_type + template_hint
  │   只选 prompt 上下文与 few-shot，不发 LLM 请求
  ▼
⑤ LLM 结构化抽取（chat_json）
  ├─ system prompt（字段来源表 + 12 条抽取规则 + review_issue 输出规范）
  ├─ few-shot（按路由选 1 个最相关样例，启动时加载 references/）
  ├─ TuoshuOutput JSON Schema 强约束，temperature=0
  └─ 归一化（normalize_llm_output：中文 key 矫正 + review_issue 结构校验
     + 单次修复重试）
  ▼
⑥ 确定性合并（merge_deterministic_values）
  └─ 模板锁定值覆盖 LLM 值；冲突 → deterministic_ai_conflict（blocking）
  ▼
⑦ 后处理管线（postprocessor.finalize_extraction，30+ 项校验/修复）
  ├─ 显式字段恢复（标签正则/表格列/碎片日期/模板特判）
  ├─ 单据号/箱号/封号 sanitize + 原文逐字校验
  ├─ grounding（自由文本必须原文有依据）
  ├─ 承运人来源判定（明示/前缀推断/船名推断）
  ├─ 港口/日期/数值/箱型归一
  └─ review_issues 白名单过滤 + 去重 + 确定性排序
  │
  ▼
⑧ 订单映射与就绪判定
  ├─ order_mapping：c_sn/mbl_no/hbl_no/c_title/factory_name/c_note
  ├─ ready_for_order = 无 blocking issue
  └─ TuoshuOutput 校验 → 响应 {skill, version, data, meta, content}
```

**关键点**：确定性规则（②③④⑥⑦）与 LLM（⑤）分层，确定性永远压过 LLM；LLM 只做「看文档填字段」，所有业务安全校验在代码层兜底。

## 3. 文档转换与解析器路由

### 3.1 内容格式识别（detect_document_format）

按 magic bytes 识别：PDF（%PDF-）、OLE2（.xls/.doc 容器）、RTF、HTML、Word XML、ZIP（按内部结构区分 docx/xlsx）、图片（JPEG/PNG/GIF/BMP/TIFF/WEBP 各自签名）。扩展名与内容不符 → 400 file_format_mismatch（`.xls` 兼容 OOXML 工作簿、`.doc` 兼容 word_xml/rtf/html）。

### 3.2 PDF 页级质量探测路由

启用 MinerU 时，逐页探测 `probe_pdf_page`：

- 合格条件：字符数 ≥ `parser_text_min_chars`（50）、乱码率（\ufffd + cid:）≤ `parser_garbled_ratio_threshold`（0.05）、关键标签（船名/提单号/主单号/件数）无 bbox 重叠
- 合格页 → pdfplumber 本地提取（表格转 pipe markdown）
- 不合格页 → 渲染 PNG 送 MinerU OCR（多页并行，并发 `mineru_ocr_concurrency`）；MinerU 失败/低置信 → 该页 vision 兜底 + blocking issue
- vision 页数超 `vision_max_pdf_pages`（10）→ 422 pdf_page_limit_exceeded

### 3.3 图片通道

- MinerU 启用：原图直传 OCR；**高置信时跳过 LLM vision** 只用 OCR 文本（`image_vision_skip_when_confident`）——MinerU 已给结构，原图只做低成本独立核对
- MinerU 失败/低置信：回退 vision（原图 base64 直传 LLM）
- 图片总字节超 `vision_max_image_bytes`（8 MB）：有 OCR 文本 → 降级纯文本 + blocking；无 OCR 文本 → 直接拒绝（422，绝不允许空文档喂 LLM 产出捏造数据）
- LLM 无视觉能力（`llm_vision_enabled=false`）：跳过 vision，MinerU OCR 文本走 LLM + 强制人工复核

### 3.4 扫描 PDF 兜底

无文本层 PDF（SCAN_OR_IMAGE_HINT）：
- LLM 无视觉 → MinerU OCR 整篇 → 纯文本抽取 + blocking `scanned_pdf_ocr_unverified`
- LLM 有视觉 → 渲染每页 PNG 直传 vision + 每页 blocking `vision_only_unverified`

### 3.5 转换降级标记

- Excel 公式无缓存值 → `formula_value_unavailable`
- 附件存在未覆盖内容（coverage.complete=false）→ `conversion_coverage_incomplete`
- Word 内嵌图片 → 逐张送识别，成功加 `embedded_image_requires_review`（防印章/logo/水印误当正文），失败加 `embedded_image_unprocessed`
- 以上全部进 review_issues，不静默

## 4. 模板识别（两级）

### 4.1 确定性模板（map_template）

| 模板 | 判定 | 锁定字段 |
|---|---|---|
| `neizhuang_booking` | 含「内装箱委托书」且表内值 ≥3 项，或船公司/船期/中转港/要求进港四标签齐全 | carrier/etd/transit_port/remark |
| `bingsheng_transport` | 表头序列指纹（sha256 精确匹配：主单号/船名/航次…地址/时间）+ 必需关键词 | doc_type/internal_ref/mbl_no/vessel/voyage/pol/pod/terminal/etd/transit_port/containers/factory/shipper_company 等全量 |

哨兵校验：bingsheng 指纹命中但主单号非法/日期缺失 → `template_mismatch`（blocking）并降级通用 AI 路线。

## 5. LLM 抽取契约

- 输出受 TuoshuOutput JSON Schema 强约束（`_clean_json_schema` 展平 $defs/anyOf 为模型友好形式）；temperature=0
- review_issue 结构无效 → 单次修复重试：只重发 review_issues 数组（不重输出整份 JSON），重试耗时 ~20s
- 系统提示硬约束：
  - review_issues 的 code 只能使用预定义集合，**严禁自创 missing_* 等未定义 code**（后处理层白名单过滤兜底）
  - field 必须用标准字段路径，禁止 `containers[]` 无索引占位
  - 编号/人名逐字复制；红章/水印/logo/OCR 一律忽略
  - 关单号即提单号；报关单号/运编号/业务编号不是提单号
  - 开港时间不是 etd；截单/截关不是做箱时间
  - 数字不求和、不换算（吨转 KG 除外）；≤0 清空
  - 自由文本必须原文有依据（ungrounded_text blocking）
  - 老式 .doc 展平的 `_pN_` 段落流有专门恢复规则

## 6. 后处理管线（finalize_extraction）

### 6.1 执行顺序（代码顺序，不可随意调换）

1. review_issues 归一化 + 去重 + `_ALWAYS_BLOCKING_CODES` 强制 blocking
2. 显式字段恢复（`_restore_explicit_header_fields`）：recipient/doc_date/carrier/customer_ref/shipper_agent/customer/loading_time/etd/transit_port/要求进港时间
3. 模板特判（`_apply_template_field_overrides`：bolian_segway 抬头工厂）
4. 「请注意」编号列表备注恢复（合并去重，非阻断提示）
5. 发货联系人校验（必须来自 FROM/FM 联系人栏）
6. 人名逐字校验（`person_name_not_verbatim`；vision 输入无原文 → `person_name_unverified`）
7. 中转港待查描述恢复/冲突（`conflicting_transit_port`）
8. 子提单号恢复与误判修复（`hbl_misclassified_as_mbl`）
9. 托运人公司来源校验（`shipper_company_not_from_explicit_field`）
10. 箱号/封号格式 + 逐字校验（`invalid_container_no`/`invalid_seal_no`）
11. 单据号 sanitize（`invalid_mbl_no`/`invalid_hbl_no`/`mbl_no_by_format`）
12. 提单号从原文恢复（按格式特征定位，排除纯字母与数字+单位）
13. 明细箱型优先于总箱量（冲突时以明细为准）
14. 箱型保真（HQ/HC/DV/GP 不得改写；非标保留 + 非阻断提示）
15. 测量值 sanitize（≤0 清空；吨转 KG）
16. 件数单位恢复
17. 港口归一（州/国家修饰保留；中转港/目的港互不混淆）
18. 单柜提单号继承
19. 船期缺年份处理（推断失败 → 置空 + `etd_year_missing`）
20. 承运人来源判定（前缀冲突修正 + `carrier_prefix_mismatch`/`carrier_by_mbl`/`carrier_by_vessel`）
21. 柜备注索引恢复（「柜N备注：」→ containers[N-1].remark）
22. OCR 伪影清除（`confirmed_ocr_artifact`）
23. 空备注子句清理
24. grounding（`_ground_free_text_fields`：remark/柜备注/封号必须原文有依据）
25. 日期 schema 校验
26. 柜级冲突检测（`conflicting_container_data`）
27. 缺失测量值恢复/标记
28. 必提取字段缺失终判（mbl_no/customer/address/loading_time）
29. review_issues 白名单过滤 + 去重 + 排序（优先级/code/field 三元组，确定性输出）
30. ready_for_order = 无 blocking
31. order_mapping 组装

### 6.2 review_issue 白名单体系

- `_KNOWN_REVIEW_ISSUE_CODES`：代码可生成/认可的 code 全集；LLM 自创 code 一律清除
- `_ALWAYS_BLOCKING_CODES`（约 40 个）：deterministic_ai_conflict/template_mismatch/mineru_failed/mineru_low_confidence/ungrounded_text/conflicting_container_data/missing_mbl_no/missing_customer/missing_address/missing_container_type/missing_container_measurements/carrier_by_mbl/carrier_by_vessel/invalid_container_no/invalid_seal_no/person_name_not_verbatim 等，无论 LLM 标什么一律强制 blocking
- 非阻断：vision_cross_check_skipped/etd_year_missing/unknown_container_type/notice_remark_restored/missing_loading_time 等
- 排序优先级：missing_mbl_no=10、missing_container_measurements=10、missing_address=30、missing_container_type=30、carrier_* =40，其余 50

### 6.3 关键业务规则（沉淀）

- **客户来源**：FM/FROM 后的公司名（排除抬头货代、收件方）→ 明确客户栏/客户简称/客户名称 →「客户简称+装箱/做箱通知」抬头 → 正文抬头公司；文件名前缀不是来源；做箱工厂不是客户
- **托运人公司**：正文明确发货人/托运人栏位；bingsheng/bolian_segway 模板抬头公司双写 shipper_agent+shipper_company；其他模板禁止把工厂/抬头货代当托运人
- **提单号**：≥8 位数字或字母数字（纯字母不算）；去空格连字符；子提单号误填为主提单号时清空主提单号并标记
- **承运人**：原文明示值（含 `EMC CPS` 全称）> 提单号前缀推断 > 船名推断；推断必须带 blocking issue 并列依据
- **中转港**：「见设备交接单/见设备单/见 EIR」等待查描述**逐字保留**；与具体值并存 → blocking 冲突
- **grounding**：图片输入时原图可见文字是最终依据，OCR 文本只是辅助；OCR 中有但图片看不到的词句必须剔除 + blocking

## 7. 确定性 vs LLM 的冲突处理

| 场景 | 处理 |
|---|---|
| 确定性模板值 vs LLM 值不同 | 保留确定性值 + `deterministic_ai_conflict`（blocking） |
| 原文明示值 vs LLM 值不同 | 原文值覆盖 + 对应 issue（如 `hbl_no_not_verbatim`） |
| 路由 doc_type vs LLM doc_type 不同 | 路由值强制覆盖（模板正确命中时不误报冲突） |
| 提单号前缀 vs LLM 承运人不同（原文无明示） | 前缀值覆盖 + `carrier_prefix_mismatch`（blocking） |

原则：**代码规则 > 原文 > LLM**；任何覆盖都必须留痕（review_issue），不静默。
