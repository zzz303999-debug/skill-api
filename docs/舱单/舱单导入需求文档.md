## 2. 背景与目标

### 2.1 背景

船司/同行提供的英文舱单（Excel）目前需人工逐字段录入 TMS「舱单管理」，成本高且易错。现有 3 份模版（实测为 2 个家族）：

- 表单式布局（label → value + 大量合并单元格），与竞品账单（行式表格）形态不同，不能复用表头列映射方案
- 全英文内容；TMS 起运港为自由输入（2026-08-19 需求变更：原为 22 中文港下拉，已取消英文→中文映射）
- 存在双提单号（斜杠分隔）、日期无年份、列位移、脏数据（多点号数字）等坑

### 2.2 目标

- 上传舱单 `.xlsx` → 自动解析 → 产出 TMS 舱单新增 payload → 预览或逐单创建
- 沿用竞品账单导入的成熟闭环：预览 → 人工确认 → 逐单创建、成功单去重注册表、单失败隔离、不自动重试

### 2.3 范围界定

| 范围 | 内容 |
|---|---|
| v1 | 舱单头字段（提单号/船名航次/港口/收发通三栏/品名/件毛体/唛头）+ 箱型箱量（每箱运价恒 0，§6.6） |
| 不在 v1 | 费用录入（`ysFees`/`yfFees` 恒发空数组）、客户匹配建档（`cId`/`cTitle` 相关，留 v2） |
| 不填（TMS 系统侧字段） | 业务状态、是否换单、放箱状态是否完成、下单时间、下单员、目的港费用是否支付、是否清关放行、订单来源 |

### 2.4 核心设计原则

1. **默认不自动录入**：`create_order` 缺省 false，只预览；显式 true 才逐单创建
2. **一文件一票**：舱单为单票文件；出现多票文件再扩展归集
3. **零静默错误**：必填（提单号/箱型箱量/起运港）缺失 → `missing_fields` 标记 + 中文原因，create 模式拦截该单，preview 只报告；关键数字宁缺勿错
4. **不自动重试**：创建失败单由调用方处理后重提；失败单不登记去重
5. **原文保真**：提单号、公司名、品名等逐字复制，不做智能改写
6. **不猜测填充**：解析不到或映射不出的字段一律置空/标记缺失，不以推测值填充（含港口、船公司等待确认项）

## 3. 名词解释

| 术语 | 说明 |
|---|---|
| 舱单 | 船司/同行提供的单票运输信息文件（托书或 SI） |
| 托书 | Entrusting Book / Authorization Form，委托方出具的委托单（家族 A） |
| SI | Shipping Instruction，托运指示（家族 B，SITC 航线） |
| 家族 | 同源模板集合；同家族布局一致，允许行号漂移与列位移 |
| 预览模式 | 只解析不触达 TMS，零副作用（不读写任何注册表） |
| 创建模式 | 解析后逐单调用 TMS 舱单新增接口 |
| 成功单注册表 | 提单号 → 首次创建回执的去重登记（独立存储文件） |

## 6. 功能需求

### 6.1 文件上传与格式校验

- `POST /orders/manifest/import`（草案，见接口文档），`multipart/form-data`：`file`（必填）+ `create_order`（bool，缺省 false）
- 仅支持 `.xlsx`（magic bytes 校验，PK 头）；扩展名不符/空文件/损坏 → 400
- 大小上限沿用服务既有约束（20 MB）
- 解析在线程池执行（并发上限 4、排队超 10 秒 503，沿用全局约束）

### 6.2 家族识别

- 依据 sheet 名 + 标题锚点：`Entrusting books` / `Sea Freight Import Authorization Form` → 家族 A；`Shipping Instruction` / `Template BL / Actual Data SI` → 家族 B
- 未识别 → 400（错误码见接口文档草案）
- 布局容忍：label 定位 + 合并单元格填充，不依赖固定行号/列号

### 6.3 提取规则

- **船名/航次拆分**：去日期括号后，末尾独立 token 匹配 `\d{3,}[A-Z]`（2617N/2618N）为航次，其余为船名（与样例 `CHENNAI VOYAGER`/`2607N` 一致）
- **双提单号**：斜杠双号整串入 bOrderNum（已确认）
- **SAME AS CONSIGNEE**：通知人姓名/地址/电话取收货人对应值（§6.10）
- **箱明细内容模式识别**：见 §4.3（防列位移）
- **脏数字清洗**：多点号归一、千分位、浮点尾巴；件数/毛重/体积缺失置 null
- **原文保真**：公司名/品名/提单号逐字复制（仅 strip 首尾空白）

### 6.4 必填与缺失处理

| 必填 | 缺失时 |
|---|---|
| 提单号 bl_no | missing 标记；create 拦截该单 |
| 箱型箱量 box_groups | 同上（含 SI 变体 1 无箱型场景、箱型无箱量变体）；白名单外标准码 → 文件级拒绝（§6.5，非 missing 拦截） |
| 起运港 pol → bStartPort | 同上（POL 缺失；自由输入原文，无映射） |
| 箱量 ctnNum | 含于 box_groups 必填（2026-08-19 确认：箱量必填） |

缺失不阻塞 preview 返回；create 模式逐单拦截（拦截单不提交、不登记去重）。

### 6.5 箱型白名单校验（文件级，同账单 v1.3）

- preview 与 create 统一执行：任一单含白名单（`config/box_type_whitelist.yaml`，与竞品账单同一份）外**标准代码箱型**（如 40GOH）→ **全部未决单拒绝**（`unknown_box_type`），不调下游、零副作用
- 非标表述（大冷/飞翼车/拼箱等账单侧已放行的形态）不校验、照常提交（舱单模版实测均为标准码，如 40HQ）
- 箱型整体缺失（SI 变体 1 无箱型来源）不属白名单问题，走 §6.4 missing 拦截

### 6.6 每箱运价

- **恒 0**（2026-08-20 修正）：TMS 误将 `unitPrice` 设为必填项，舱单模版实际无运价字段 → 先默认 `0`（字符串 `"0"`）满足必填校验
- v1.0/v1.1 的"服务端配置运价表按箱型取值、查不到 create 拦截"口径作废（`manifest_price_map` 已移除）；后续如需真实运价再扩展
- totalPrice 恒 `0`（= unitPrice × ctnNum，数字）；不参与必填缺失拦截

### 6.7 预览/创建双模式

- preview：解析 + 起运港（POL 原文）结果预览；**零下游调用、零注册表读写**；返回 `order_data`（待提交的上游请求体，人工核对用）
- create：逐单提交 TMS（端点/鉴权【待确认】§8-9），单失败隔离不中断整批；sk 缺失 400；返回 `order_data`（实际提交的请求体）
- 响应语义对齐竞品账单导入：`orders[].create_result` + `summary` + `upstream`

### 6.8 去重

- 成功单注册表独立存储（`storage/imported_manifests.json` 草案）；提单号 strip + 大写规范化为业务键
- first-write-wins；lookup→submit→register 临界区 per-bl_no 分段锁；失败单不登记，重导照常提交
- create 模式全部命中（无新建）→ 409
- **force 重导**（v1.6）：`force=true` 跳过去重查重——注册表不知晓 TMS 侧删除动作，
  TMS 删单后重录场景由调用方显式强制（重复录入风险自负；仅跳过查重，必填/白名单
  拦截不受影响）

### 6.9 错误处理

- 统一走全局异常处理（`{"error": {code, message, description, details}}`）；新错误码在 `ERROR_CODE_DESCRIPTIONS` 登记中文说明
- 下游网络错误/超时按单记 `create_result.error`，不自动重试

### 6.10 三栏大格拆分（名称/地址/电话）

2026-08-20 TMS 实测核查发现：三栏数据（名称+地址+电话+VAT/PIC/邮箱）糊在
同一合并大格里，此前整块进 `*Name` 而 `*Tel`/`*Address` 恒空。拆分规则
（`_split_party_block`，未匹配部分原文保真、不猜切分）：

- **电话**：`Tel:` / `Phone number:` 等标签后取号；无标签时按 11 位大陆
  手机号形态识别；取走后从原文移除；
- **剔除无落点项**：邮箱、`VAT:` 行、`PIC:` 行、`Receiver:`/`Contact:`
  联系人段（TMS 三栏无对应字段）；
- **地址**：`Registered Address：` / `ADD:` 行取冒号后内容；单行连排按
  ① ≥4 连续空隙且后半含数字（SI v1 排版）② ` No. `/`NO .` 编号地址起点
  切分；
- **名称**：余下文本；无任何标记（如托书发货人格）→ 整块进名称；
- **SAME AS CONSIGNEE**：展开为收货人的名/地址/电话三元组；
- 已知残留：SI 收货人地址尾部可能带联系人名（如 "…China Guo daijun"，
  电话取走后无标记可切，宁残留不误删）。
