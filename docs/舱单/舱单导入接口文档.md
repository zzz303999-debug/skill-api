## 1. 概述

### 1.1 背景

英文舱单（托书 / SI，`.xlsx`）需录入 TMS「舱单管理」。本服务负责：解析舱单 → 提取字段 → 港口映射 → 组装 TMS 舱单新增 payload（每箱运价恒 0，§2.2）→ 按开关**只返回预览**或**逐单创建**。

模板实况与字段映射依据见《舱单导入需求文档》§4/§5。

### 1.2 接口形态（草案）

**单接口 + 开关**：`POST /orders/manifest/import`，`multipart/form-data`：

| create_order | 行为 |
|---|---|
| `false`（默认） | 只解析并返回预览（含提取结果、缺失字段），**不触达 TMS** |
| `true` | 解析后**逐单创建**舱单，响应同时返回每单创建结果与汇总 |

> **重复导入（v1.9）**：create 模式不再本地去重，同一文件/同提单号重复上传照常重新提交（重复风险调用方自负）；`force` 参数已移除，summary `skipped` 保留恒 0（结构对齐账单导入）。

### 1.3 核心原则

1. **默认不自动录入**：`create_order` 缺省 false，防止误录入
2. **一文件一票**：单票舱单文件；文件含 ≥2 个不同提单号（多票）→ 文件级拒绝 `manifest_multi_bl_no`（v1.8）
3. **零静默错误**：必填缺失不阻塞 preview，create 模式拦截该单并给出中文原因；关键数字宁缺勿错
4. **不自动重试**：防止重复录入；失败单由调用方处理后重提
5. **不猜测填充**：解析不到/映射不出的字段置空或标记缺失

## 2. 业务流程

### 2.1 上游侧流程（调用方视角，草案）

```
① POST /orders/manifest/import（multipart）
   file: 舱单文件（.xlsx）
   create_order: false（缺省，只预览） | true（直接创建）
      │
      ├─ create_order=false → 返回 orders[] 预览（字段提取/起运港/missing_fields + order_data 待提交请求体）
      │
      └─ create_order=true  → 逐单创建，返回 orders[].create_result + summary + upstream
```

- 预览模式**零下游调用**（零副作用）
- 创建模式某单失败不影响其他单；失败原因完整透传
- **重复导入（v1.9）**：create 模式不再本地去重，重复上传照常重新提交（重复风险调用方自负）
- 修正字段需修改舱单文件后重新导入（单接口模式，无独立提交通道）

### 2.2 下游侧链路（调用方 → 服务端 → TMS 舱单新增）

- 端点（2026-08-19 抓包已确认）：`POST https://service.jxt56.com/crm/order/bill/addBill`，请求体为 JSON（与账单 AddWork 的 form-data 通道不同）
- 鉴权（已确认）：请求头 `sk: <token>`（调用方登录 TMS 获取，create 模式随请求头透传，服务端不落盘）；`Content-Type: application/json`

**响应契约**（2026-08-19 抓包 + 2026-08-20 live 实证）：

- 成功判定：`code` **数字 200** 即已创建（与账单 AddWork 的字符串 `"200"` 不同，判定时不可混用）。**服务端通道实测 `data` 恒为 null 但订单真实落库**（TMS UI 核实 7 条），msg "成功" 可信；`data[0]` 创建对象回执（含 `bId`，如 11801）**仅浏览器通道可得** → 服务端调用 `create_result.sn` 记空串，去重完全依赖本地注册表（§4.6）
- 失败判定：`code != 200` 视为失败，`msg` / `errorMsg` 透传入 `create_result.error.details.upstream_msg`（**失败样本已 live 实证**，2026-08-20：`code "204" + msg 中文原因`，如"英文品名不能超过100个字符"；另实测异常形态：`bOrderNum` 含斜杠 → 插入后返回 HTTP 500 + 无 code/msg 的 JSON 体，但订单已创建，故斜杠号必须在提交前拆分）
- 实证：cTitle/cSn 发空串可正常创建（浏览器端回显 null，bId=11801）

**payload 字段类型口径**（最小 payload 实测，2026-08-19）：

| 字段 | 类型 | 实测值例 | 说明 |
|---|---|---|---|
| type / ieFlag | number | 2 / 1 | 恒 2 / 1（2026-08-19 确认，抓包样例） |
| bOrderNum | string | `"SITGBAQI005920"` | **不支持斜杠**（2026-08-20 实测：含斜杠 → 下游 500）；v1.8 起斜杠双号文件级拒绝（`manifest_multi_bl_no`），提交不再可达斜杠（bl_no 展示取后段船司号，取后段为防御口径） |
| goodsEname | string | `"silicon wafer"` | **≤ 100 字符**（2026-08-20 实测超长 → 204"英文品名不能超过100个字符"）：品名块剔除 INVOICE No./HS CODE 元数据行，不硬截断 |
| unitPrice | string | `"0"` | **恒 `"0"`**（2026-08-20 修正）：TMS 误设必填，模版无运价字段 → 先默认 0 满足必填校验（v1.1 的"运价表按箱型取值、查不到拦截"作废） |
| totalPrice | number | 0 | **数字**（恒 0 = unitPrice × ctnNum） |
| ctnNum | number | 1 | 箱量（必填，2026-08-19 确认） |
| bDate | string | `"2026-08-19 15:38"` | 格式 `YYYY-MM-DD HH:mm`；v1 留空（2026-08-19 确认；模版无年份不猜测补年） |
| bTotleNum/Weight/Bulk | string | `""` | 单头件/毛/体，字符串 |
| cId | string | `""` | 未匹配客户时空串（非 null） |
| 其余未取到字段 | string / [] | `""` / `[]` | 空串/空数组，不用 null 填充（与预览 order_data 缺失置 null 的展示口径区分：**提交侧空串，展示侧 null**） |

## 3. 请求

### 3.1 参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `file` | form-data | file | 是 | 舱单文件，仅 `.xlsx`，magic bytes 校验，上限 20 MB |
| `create_order` | form-data | bool | 否 | 缺省 false；true 时逐单创建 |
| `sk` | header | string | create 模式必填 | TMS token，原样透传下游【待确认】 |

**curl 示例**（create 模式）：

```bash
curl -X POST http://<host>:9000/orders/manifest/import \
  -H "Authorization: Bearer <API_KEY>" -H "sk: <TMS token>" \
  -F create_order=true \
  -F "file=@舱单.xlsx"
```

> 预览模式：`create_order` 缺省（false）、不带 `sk` 头即可，零副作用；`force` 参数已于 v1.9 移除（放开本地去重，重复上传照常提交）。

### 3.2 错误码（草案；实现时在 `ERROR_CODE_DESCRIPTIONS` 登记）

| HTTP | code | 场景 |
|---|---|---|
| 400 | `bad_request` | 缺 file / create 模式缺 sk |
| 400 | `file_format_mismatch` | 扩展名与内容不符（非 PK 头） |
| 422 | `convert_error` | 文件损坏/无法解析 |
| 400 | `unknown_manifest_family`（草案） | 家族未识别（非托书/SI 布局） |
| 400 | `unknown_box_type` | 任一单含白名单（`config/box_type_whitelist.yaml`）外标准码箱型 → 全部未决单拒绝（同账单 v1.3；preview 亦拒绝） |
| 400 | `manifest_box_missing`（v1.7） | 解析未提取到箱型（SI 变体 1 等）→ 文件级拒绝（preview 亦拒绝；create_result 标记 + `data.upstream` 为 null，不伪造上游回显，同 `unknown_box_type` 形态） |
| 400 | `manifest_multi_bl_no`（v1.8） | 文件解析提取到 ≥2 个不同提单号（多票）→ 文件级拒绝（preview 亦拒绝；create_result 标记 + `data.upstream` 为 null，不伪造上游回显，同 `manifest_box_missing` 形态） |
| 503 | `server_busy` | 解析排队超时（沿用全局并发约束） |

> **外壳成功语义（v1.10）**：preview 成功 = `code="200"` + `msg="请求成功"`（整批被拒——箱型白名单/箱型缺失/多提单号——时 `msg` 为具体原因文案，`code` 保持 `"200"`）；create 创建成功 = `code="200"` + `msg="添加成功"`；create 全部失败 = `code="204"` + `msg` 优先为具体拦截/失败原因（如"系统没有此箱型：40GOH，请联系客服"）、无则 `"添加失败"`（对齐账单录入 v2.2 口径）。
>
> `start_port` = POL 原文清洗（自由输入+必填，2026-08-19 已确认；清洗仅去首尾空白，拼写保持原文保真）；`orderInfos[].unitPrice`/`totalPrice` 恒 `"0"`/`0`（2026-08-20 修正，见 §2.2）。
>
> **`order_data` = 上游下单请求体回显**（v0.3）：preview 返回**待提交**请求体（人工核对用），create 返回**实际提交**的请求体；必填未取到时对应键置 `null`（不用 0/空串填充猜测值，如上例 `bDate`）；`type`/`ieFlag` 恒 2/1；门点（`shipperFactory*`/`consigneeFactory*`）等模版无来源键示例从略，完整键集以冻结版需求文档 §5 映射总表为准。

### 4.3 缺失语义

必填三项：`bl_no` / `box_groups`（含箱量） / `start_port`。（每箱运价恒 `"0"`，2026-08-20 起不属必填、不参与缺失拦截。）

- preview：`bl_no`/`start_port` 缺失只标记，正常返回；**`box_groups` 缺失直接拒绝**（v1.7）
- create：`bl_no`/`start_port` 缺失单**拦截不提交**（`create_result` 填充拦截结果，错误码 `manifest_order_not_ready`）；**`box_groups` 缺失文件级拒绝**（`manifest_box_missing`，v1.7）
- 箱型白名单（同账单 v1.3）：任一单含白名单（`config/box_type_whitelist.yaml`）外**标准代码箱型**（如 40GOH）→ **全部未决单拒绝**（`unknown_box_type`，含合法箱型单一并拒绝），不调下游；preview 亦拒绝；非标表述（大冷/拼箱等）不校验照常提交
- **箱型整体缺失**（v1.7）：解析未提取到箱型（SI 变体 1 无箱型来源、箱型无箱量变体）→ 文件级拒绝 `manifest_box_missing`（preview 亦拒绝、不调下游），形态对齐 `unknown_box_type`（create_result 标记 + `data.upstream` 为 null）；box_groups 为空不触发白名单拒绝，两者互斥
- **多提单号**（v1.8）：文件解析提取到 ≥2 个不同提单号（多票）→ 文件级拒绝 `manifest_multi_bl_no`（preview 亦拒绝、不调下游），形态对齐 `manifest_box_missing`；同一提单号重复出现不算多票；**MBL NO 斜杠双号（参考号/船司号）按 `/` 拆分为两个提单号计入**（2026-08-21 晚用户拍板）；HBL NO 分单不参与计数

### 4.4 create_result（对齐账单导入惯例）

`create_result` 固定六键，缺省键恒输出不省略（`skipped` 默认 false，`o_id`/`upstream`/`error` 默认 null）；`error` 为三元组 `{code, message, details}`，与账单导入同构（无 description）。

| 场景 | 结构 |
|---|---|
| 成功 | `{"success": true, "skipped": false, "sn": "<bId>", "o_id": null, "upstream": {…data[0] 原始回显…}, "error": null}`（sn = addBill 回执 `data[0].bId`；服务端通道 data 恒 null → sn 空串、upstream null） |
| 失败 | `{"success": false, "skipped": false, "sn": null, "o_id": null, "upstream": null, "error": {"code", "message", "details"}}` |
| 必填拦截（bl_no/pol） | 同失败，code=`manifest_order_not_ready`，details 含 missing_fields |
| 箱型缺失拦截（v1.7） | 同失败，code=`manifest_box_missing`，details 含 missing_reasons；`data.upstream` 为 null（不伪造回显）；preview 亦拒绝 |
| 多提单号拦截（v1.8） | 同失败，code=`manifest_multi_bl_no`，details 含 bl_nos；`data.upstream` 为 null（不伪造回显）；preview 亦拒绝 |

> v1.9 起移除「去重命中」行（放开本地去重，不再 skipped；`skipped` 键仍恒输出 false）。

### 4.5 summary（create 模式）

`{"total", "success", "failed", "skipped", "created", "success_sns", "failed_details"}`（口径与账单导入一致；v1.9 起 `skipped` 恒 0——放开本地去重，无 skipped 语义）。`failed_details[]` = `{"order_num", "code", "message"}`（order_num=提单号；键口径对齐账单 R4/R5）。

`upstream`（顶层 `data.upstream`，create 模式）：有新建成功 → `{"code": "200", "msg": "添加成功", "data": [成功单原始回显…]}`（无回显时 `data` 为 `[]`）；全部失败/拦截 → `null`（不伪造上游回显，对齐账单 R3）；preview 恒 `null`。

### 4.6 去重语义（v1.9 起放开）

- **v1.9（2026-08-21 用户拍板）**：create 模式**不再本地去重**——不查成功单注册表、不登记、不 skipped；同一文件/同提单号重复上传照常重新提交（重复风险调用方自负）；`force` 参数与 409 `duplicate_manifest` 移除；注册表模块暂停生产使用（历史数据 `imported_manifests.json` 保留，供回滚/恢复）
- 失败单照常可重导重试（行为不变）
- 必填拦截/箱型白名单不受影响；多提单号文件级拒绝（v1.8）不受影响（与去重维度独立）

**调用方迁移指引（v1.9）**：旧契约下以 409 `duplicate_manifest` / summary `skipped>0` 识别重复上传、以 `force=true` 做 TMS 删单后重录；v1.9 起重复上传恒返回 200 且 `summary.created=1`，重复与否在响应中不可区分——重复/幂等由调用方自行对账（TMS 侧查询或 `success_sns` 比对），**并发重复提交同一提单号不再被服务端拦截**（per-bl_no 锁已随注册表移除）。
