## 0. 背景与收官标准

异步化改造已完成（分支 `refactor/async-split-main`）：客户端双轨异步化 →
编排/路由全链路 async → skill 契约 async 化与线程池退役 → 同步死代码删除 →
结构规范化收官。

**遗留问题**：仍有 4 类"网络调用藏在 to_thread 线程池里"的残留——不阻塞
事件循环（占线程池线程兜底），但违背"CPU 段 to_thread、网络段 async"的
分层约定（架构说明 §3.2），且无法复用共享 AsyncClient 连接池。

**收官标准**（全部达成即改造完成）：

1. 生产链路所有 LLM 调用走 `achat` / `achat_json`（真异步）；
2. 生产链路所有 MinerU 调用走 `parse_document_async`；
3. `ThreadPoolExecutor` 在 app/ 内零残留（executor.py 的信号量除外）；
4. 同步双轨零调用方后整体退役（§5 清单）。

## 2. 改造项一：bill 域 ai_header L3 映射异步化（A）

### 方案对比

| 方案 | 思路 | 评估 |
|---|---|---|
| ① 两段式拆分（**推荐**） | 解析段在 L3 未命中处停下，编排层 await LLM 后二次进段 | 架构正、终态干净；parser 改动集中在 L3 分支 |
| ② run_coroutine_threadsafe 桥 | map_header 保持同步签名，内部把 LLM 调用桥回主事件循环 | parser 零改动，但需全局 loop 引用，隐蔽全局状态，review 难 |
| ③ 暂缓 | L3 低频，维持现状 | 收官标准 1 达不成，chat/chat_json 无法退役 |

选 ①：常见路径（L1/L2 指纹命中）零额外开销；仅 L3 未命中新模板才走两段。

### 两段式设计

`_parse_with_engine`（[parser.py:855](../app/orders/bill/parser.py)）L3 分支拆出：

```
第一段（to_thread，CPU）：
  打开 workbook → template_store.identify
  ├─ L1/L2 命中 → 完整解析返回 ParseOutput（现有路径，不变）
  └─ 未命中    → 返回内部信号 _AiHeaderNeeded(view, zone_lines)
                  （zone_lines = format_header_zone(view)，纯 CPU）

async 层（编排）：
  await achat_json(_build_messages(zone_lines), json_schema=_AI_SCHEMA)
  ├─ LLMError / ParseError → to_thread(_parse_exact)（回退精确匹配，语义不变）
  └─ 成功 → 第二段

第二段（to_thread，CPU）：
  四道校验闸门（现有 _sample_check 等）→ AiHeaderResult 组装
  → build_template_config → _parse_with_template(view, ...)（复用第一段的 view）
```

### 改动文件

- `app/orders/bill/ai_header.py`：`map_header` 拆为 `_build_messages`（已有，
  纯函数）+ `validate_ai_result(view, raw, meta)`（校验闸门 + 组装，纯 CPU，
  从现 map_header 后半段迁出）；`chat_json` import 删除。
- `app/orders/bill/parser.py`：`_parse_with_engine` L3 分支改为返回
  `_AiHeaderNeeded` 信号；新增接受 `AiHeaderResult` 完成解析的入口
  （`_parse_with_ai(view, ai, engine, filename)`，内容即现 897-928 行）。
- `app/orders/bill/service.py`：`_parse_stage` 编排两段逻辑（捕获信号 →
  await → 二次进段）；`build_result_async` 语义不变。

### 测试适配

- `tests/orders/bill/conftest.py:30`：patch 目标 `chat_json` → `achat_json`
  （fake 改 `async def`，全局"LLM 不可用"拦截语义不变）；
- `test_route.py:1044`、`test_template.py:70`：同上改 patch 点与 fake 形态；

## 4. 改造项三：tuoshu 域 MinerU 全量异步化 + 线程池并行政造（C+D）

tuoshu 有 4 处同步 MinerU 调用与 1 处 ThreadPoolExecutor 并行，整体思路与
改造项二同构（转换段拆 CPU/网络），额外动作是页级 OCR 并行换 asyncio：

### 4.1 页级 OCR 并行（convert_service:325，核心改动）

```
现状：ThreadPoolExecutor(mineru_ocr_concurrency) 并行跑 _parse_ocr_page
     （每页 = PDF 渲染 CPU + mineru.parse_document 网络，各自新建 httpx client）

目标：asyncio.gather + Semaphore(mineru_ocr_concurrency)
  async def _parse_ocr_page_async(...):
      image = await asyncio.to_thread(_render_pdf_page, ...)   # CPU
      return await mineru.parse_document_async(image, ...)      # 网络
  异常/降级分支（MinerUContractError、mineru_fallback_enabled 回退 vision）
  语义逐行对齐 _parse_ocr_page。
```

单页路径（len(ocr_jobs)==1）同走 async 版，删除双形态。

### 4.2 其余 3 处（skill.py:327 / convert_service:490 / 594）

- skill.py:327 与 document 同构：`_prepare_stage` 拆分，扫描件分支
  `_NeedsMineruOcr` 信号 + run() 编排 await + `scanned_pdf_ocr_unverified`
  review_issue 语义不变；
- convert_service:490（图片整本）：随转换入口 async 化同步改
  `parse_document_async`；
- convert_service:594（`parse_pdf` 兜底）：改调 `parse_document_async`
  （或直接 `parse_document(...).markdown` 的异步等价）。

### 4.3 测试适配

- tests/skills/tuoshu、tests/mineru 中 patch `parse_document`/`parse_pdf`/
  `_parse_ocr_page` 的用例 → patch async 版（fake 改 async def）；
- 并行行为测试（如有页序合并断言）保持——gather 返回按页序组装，结果序
  与线程池版一致。
