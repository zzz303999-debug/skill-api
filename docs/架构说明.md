# skill-api 架构说明

> 2026-09 异步化改造后的分层规范。新增接口 / 排查问题先读本文。

## 1. 请求处理链路（自外向内）

```
客户端
  → Nginx（deploy/nginx，反代）
  → 中间件（执行序）：access_log（审计） → auth（鉴权） → rate_limit（限流）
  → 路由层  app/api/routes/*          薄壳：参数校验 + 调编排层
  → 编排层  app/orders/*/service.py   业务流程：CPU 段 to_thread、网络段 async
  → 客户端层 app/orders/*/client.py 等 下游 HTTP / LLM / MinerU 封装
  → 下游 TMS（publishCreateOrder / AddWork / addBill / 建档）
```

- 中间件**注册顺序即层级契约**（后注册者为外层）：`rate_limit → auth → access_log`，
  定义于 [app/api/app_factory.py](../app/api/app_factory.py)。被限流/鉴权拒绝的请求
  仍经外层 access_log 审计留痕，且不消耗限流配额。
- 应用组装唯一入口 `create_app()`，仅 `app/main.py` 调用它；`app/main.py` 同时保留
  拆分前的 `app.main` 命名空间作为**测试接缝**（`_AUTH_FREE_PATHS`、`_rate_limit_whitelist`
  定义于此；`build_result`、`_publish_order`、`_parse_document_to_order` re-export，
  中间件与路由在**调用时**经该命名空间解析，测试以 `setattr(main_module, ...)` 注入替身）。

## 2. 目录职责

| 路径 | 职责 |
|---|---|
| `app/main.py` | 入口：`app = create_app()` + 测试接缝 re-export |
| `app/api/app_factory.py` | 组装：中间件、异常处理器、路由挂载（顺序即契约） |
| `app/api/middleware/` | access_log / auth / rate_limit 三中间件 |
| `app/api/error_handlers.py` | 全局异常处理器（错误响应统一出口） |
| `app/api/executor.py` | skill 并发控制（`asyncio.Semaphore`，排队 10s 返 503）+ 路由异步包装 |
| `app/api/response_shell.py` | 统一响应外壳 `{code, msg, data}` 的路径注册 |
| `app/api/uploads.py` | 上传文件读取与大小校验（各上传路由共用） |
| `app/api/routes/` | 路由：meta / pages / orders / bill_import / manifest_import / skills（动态注册） |
| `app/orders/bill/` | 竞品账单导入：parser → aggregator → service → client |
| `app/orders/manifest/` | 英文舱单导入：parser → service → client |
| `app/skills/tuoshu/` | 托书抽取 skill（异步契约） |
| `app/llm/client.py` | LLM 统一入口（`achat` / `achat_json`），禁止绕过 |
| `app/document_parsers/mineru.py` | MinerU 解析客户端（`parse_document_async`） |

## 3. 异步约定（2026-09 起）

1. **路由 handler 一律 `async def`**，直接 `await` 编排层 async 版本；不允许在
   handler 内调用同步网络 I/O（会阻塞事件循环）。
2. **编排层 async 函数**（`build_result_async` / `build_manifest_result_async` /
   `run_fee_bootstrap_async` / `run_master_data_async` / `create_orders_async`）：
   - CPU 密集段（openpyxl 解析、归集聚合、payload 构造）用 `asyncio.to_thread`；
   - 网络段走 client 层 async 版本（`post_json_async` / `post_form_async` /
     `achat_json` / `parse_document_async`）。
3. **SkillBase.run 为 async 抽象契约**（[app/core/skill_base.py](../app/core/skill_base.py)）：
   新 skill 实现 `async def run()`，转换段（LibreOffice subprocess / PDF 渲染等 CPU 与
   子进程工作）内部用 `asyncio.to_thread` 包裹；并发上限与排队 503 由
   `app/api/executor.py` 的 `_inflight_semaphore` 统一控制。
4. **并发下单**：`create_orders_async` 用 `asyncio.gather` +
   `Semaphore(BILL_CREATE_CONCURRENCY，默认 4)` 有界并发；**同一提单号+箱号串行**（见 §5），
   不同键并行；单失败隔离、不自动重试（防重复订单）语义不变。

## 4. 统一响应外壳 `{code, msg, data}`

- 覆盖路径清单在 [app/api/response_shell.py](../app/api/response_shell.py)
  `_UNIFIED_RESPONSE_PATHS`（当前：`/orders/bill/import`、`/orders/manifest/import`、
  `/skills/tuoshu/extract`）；新接口适配只需把路径加入该集合，错误响应由全局异常
  处理器自动套壳。
- 未在清单内的路径保持旧结构 `{error: {code, message, description, details}}` 不变。
- 覆盖路径上所有场景（成功/业务失败/请求错误/限流/鉴权/503）统一三字段外壳。

## 5. 去重注册表与异步锁（重要）

[app/orders/bill/imported_registry.py](../app/orders/bill/imported_registry.py) 提供
**per-键异步锁 `alock_for()`**（`asyncio.Lock`，`async with`）：

- 临界区：查重 → submit → register；锁内 `await` 下游不阻塞事件循环；
- 去重键 = `提单号 + 箱号`（无箱号退化行序号）；同键串行保证 lookup→submit→register
  原子性与 first-write-wins；异键互不阻塞；
- 字典 setdefault 在单线程事件循环内无竞态；单进程单 worker 部署是前提。
- 注册表持久化：单文件 JSON + 临时文件原子替换（`imported_orders.json`）。
- 实例级进程内数据保护（ImportedOrderRegistry._lock，threading.Lock）仍保留。

## 6. 共享客户端单例（懒加载）

- `app/orders/http_client.py::get_async_client()`：共享 `httpx.AsyncClient`（连接池
  复用、per-request timeout）；检测到事件循环变化（测试场景）自动重建。
- `app/llm/client.py::get_async_client()`：共享 `AsyncOpenAI`；thinking / json_schema
  探测缓存与同步版共享。
- 不用 lifespan 管理：测试大量 `TestClient(app)` 不带 context manager，懒加载保证
  无 lifespan 时也可用。测试可直接 monkeypatch 这两个 `get_async_client`。

## 7. 新增接口开发清单

1. schema（`app/orders/<域>/schema.py`）→ service 编排（async，CPU 段 `to_thread`）
   → client 下游封装（`*_async`，三条第三方日志：request / response / request_error）；
2. 路由挂在 `app/api/routes/<域>.py`，经 `app.main` 接缝调用编排入口（保测试接缝）；
3. 需要统一外壳 → 路径加入 `_UNIFIED_RESPONSE_PATHS`；
4. 配置项加 `app/config.py` + `.env.example`（含中文注释）；
5. 测试零网络（FakeResponse / monkeypatch patch 点对齐 async 链路），提交前
   `uv run pytest -q` 全绿 + `uv run ruff check app tests` 干净。

## 8. 线程池退役说明

Phase 1-3 期间业务经 `_run_in_executor`（`ThreadPoolExecutor(skill_max_concurrency)`）
执行；Phase 4 契约统一后线程池已删除，`skill_max_concurrency` 仅作为
`_inflight_semaphore` 的并发上限继续生效（503 排队语义不变）。历史提交（6fa3bcb /
ef28a58 / 343d5db）可追溯过渡过程。
