# skill-api 架构说明

> 2026-09 异步化改造 + 结构整理后的分层规范。新增接口 / 排查问题先读本文。

## 0. 分层范式：按业务域分包（Modular Monolith）

本项目的形态 = **范式 2（按业务域分包）+ 依赖方向纪律**（不引入六边形架构的
接口抽象层——下游 TMS/LLM 为刚性契约、无第二实现可切换，抽象层是负收益）：

```
app/
├── main.py              # 入口：create_app() + 测试接缝 re-export
├── api/                 # 表现层：routes/ 薄路由 + middleware/ + error_handlers/ +
│                        #   response_shell/ uploads/ bridges/（路由→编排适配）——不承载业务
├── core/                # 横切设施：config / errors / logging_conf / skill_base /
│                        #   registry / executor（skill 并发控制）/ access_log_store /
│                        #   third_party_log_store（日志存储，被两侧共同依赖）
│                        #   ——只被依赖，不依赖域与表现层
├── orders/              # 业务域 1：四个子域自包含
│                        #   text/（自由文本下单）/ document/（附件文档抽取）/
│                        #   bill/（竞品账单）/ manifest/（英文舱单）；
│                        #   根级仅 http_client.py（三子域共享下游 HTTP 底座）
├── skills/              # 业务域 2：skill 插件（tuoshu 等），自包含
├── llm/                 # 外部适配器：LLM（OpenAI-compatible）统一入口
└── mineru/              # 外部适配器：MinerU 文档解析（client + schema）
```

根级除 `main.py` 外不再有业务模块：config / errors / logging_conf /
access_log_store / third_party_log_store 已全部收编 `core/`（2026-09 结构整理
分两批完成：先 config 三件套 + executor，后日志存储两件套）。

注：`api/` 内不设 services/ 子目录——业务编排一律下沉业务域（orders/*/service.py），
表现层与业务域的适配点收敛于 `api/bridges.py`（下单/文档解析/文本抽取三个路由入口，
即 `app.main` 测试接缝符号的宿主）。

**依赖方向纪律（硬约束，review 必查）：**

1. `core/` 不 import 任何业务域（orders/skills）与表现层（api/）模块；
2. 业务域内自包含：schema → parser/规则 → service（编排）→ client（下游封装），
   同域私有符号不出域；路由只经 service 编排入口调用，不直连 client；
3. 域间不互相 import 私有符号（bill 与 manifest 是两个独立子域）；跨域共享
   只允许经 `__init__.py` 门面或 core/；
4. 外部适配器（llm/mineru）只被域/编排引用，适配器内部不反向 import 域；
5. 测试接缝例外：路由与中间件在**调用时**经 `app.main` 命名空间解析测试替身
   （拆分兼容层，详见 §1），除此之外不得从表现层反向依赖业务细节。

新业务域落地模板 = 目录结构照抄 `orders/manifest/`（schema / parser / payload /
service / client + `__init__.py` 门面）。

**命名约定（2026-09 统一，review 必查）：**

| 后缀/关键词 | 职责 | 先例 |
|---|---|---|
| `schema` | 数据契约（Pydantic 模型 / 常量） | orders/bill/schema.py |
| `parser` | 文件解析（读源 → 结构化，无下游调用） | bill/parser、manifest/parser |
| `payload` | 下游请求体构造（字段映射对齐下游规范） | bill/payload、manifest/payload |
| `service` | 业务编排（CPU 段 to_thread + 网络段 async） | 两子域同款 |
| `client` | 下游 HTTP 封装（三条第三方日志） | 两子域同款 |
| `*_store` | 持久化存储（单例 + 临时文件原子替换） | master_data_store、access_log_store |
| `*_registry` | 注册表（去重/登记，单例 + reload_* 测试重置） | fee_registry、imported_registry |
| `*_rules` / `*normalizer*` / `aggregator` | 纯函数族（无 I/O、无编排） | document/rules、bill/normalizers |

- 文件名一律 snake_case；模块首行 docstring 用中文自述职责（专有名词可保留英文）；
- 同职责文件跨子域**必须同名**（如 bill/manifest 的 imported_registry）；
- core/ 内模块名必须精确（如 skill_registry 而非 registry）；
- 同名函数/概念禁止两种实现并存（如两套表头指纹必须以 legacy 后缀消歧）。

**代码级命名约定（2026-09 全量核查通过，新增代码必守）：**

| 维度 | 约定 | 先例 |
|---|---|---|
| 异常类 | `XxxError` 后缀；模块私有异常加 `_` 前缀 | SkillAPIError、OrderUpstreamError、MinerUError |
| 单例获取 | `get_<类型名>()`，禁止过泛的 `get_registry()`/`get_store()` | get_fee_registry、get_master_data_store、get_manifest_registry |
| 测试重置 | `reload_<对象>()`（单例重载，配合 conftest `_isolate_*` autouse fixture） | reload_templates、reload_registry、reload_store |
| 下游网络函数 | client 层 async 网络函数 `_async` 后缀；异步锁等非 I/O 原语用 `a` 前缀 | post_json_async、alock_for |
| 日志事件 | snake_case，`域_动作` 或动宾结构 | third_party_request、tuoshu_llm_start |
| error_code | snake_case（外壳业务码 `"200"/"409"/"204"` 为对齐 TMS 的对外契约，例外） | missing_bl_no、manifest_box_missing |
| settings 字段 | snake_case + 语义前缀分组（api_/llm_/mineru_/jxt_/vision_/bill_/rate_limit_/…） | llm_thinking_mode、bill_create_concurrency |
| 私有类/函数 | `_` 前缀（模块私有，不出域） | _SheetView、_RequestBodyTooLarge |
| 测试 | 模块级 `pytestmark = pytest.mark.asyncio`；替身 FakeResponse；patch 点对齐 async 链路 | test_async_clients.py |

## 1. 请求处理链路（自外向内）

```
客户端
  → Nginx（deploy/nginx，反代）
  → 中间件（执行序）：access_log（审计） → auth（鉴权） → rate_limit（限流）
  → 路由层  app/api/routes/*          薄壳：参数校验 + 调编排层
  → 编排层  app/orders/*/service.py   业务流程：CPU 段 to_thread、网络段 async
  → 客户端层 app/orders/*/client.py 等 下游 HTTP / LLM / MinerU 封装
  → 下游 TMS（publishCreateOrder / AddWork / addBill / 建档）
```

- 中间件**注册顺序即层级契约**（后注册者为外层）：`rate_limit → auth → access_log`，
  定义于 [app/api/app_factory.py](../app/api/app_factory.py)。被限流/鉴权拒绝的请求
  仍经外层 access_log 审计留痕，且不消耗限流配额。
- 应用组装唯一入口 `create_app()`，仅 `app/main.py` 调用它；`app/main.py` 同时保留
  拆分前的 `app.main` 命名空间作为**测试接缝**（`_AUTH_FREE_PATHS`、`_rate_limit_whitelist`
  定义于此；`build_result`、`_publish_order`、`_parse_document_to_order` re-export，
  中间件与路由在**调用时**经该命名空间解析，测试以 `setattr(main_module, ...)` 注入替身）。

## 3. 异步约定（2026-09 起）

1. **路由 handler 一律 `async def`**，直接 `await` 编排层 async 版本；不允许在
   handler 内调用同步网络 I/O（会阻塞事件循环）。
2. **编排层 async 函数**（`build_result_async` / `build_manifest_result_async` /
   `run_fee_bootstrap_async` / `run_master_data_async` / `create_orders_async`）：
   - CPU 密集段（openpyxl 解析、归集聚合、payload 构造）用 `asyncio.to_thread`；
   - 网络段走 client 层 async 版本（`post_json_async` / `post_form_async` /
     `achat_json`）；MinerU 解析仍在转换段 `to_thread` 内调用同步客户端
     （mineru client 已提供 `parse_document_async`，生产接入待后续迭代）。
3. **SkillBase.run 为 async 抽象契约**（[app/core/skill_base.py](../app/core/skill_base.py)）：
   新 skill 实现 `async def run()`，转换段（LibreOffice subprocess / PDF 渲染等 CPU 与
   子进程工作）内部用 `asyncio.to_thread` 包裹；并发上限与排队 503 由
   `app/core/executor.py` 的 `_inflight_semaphore` 统一控制。
4. **并发下单**：`create_orders_async` 用 `asyncio.gather` +
   `Semaphore(BILL_CREATE_CONCURRENCY，默认 4)` 有界并发；**同一提单号+箱号串行**（见 §5），
   不同键并行；单失败隔离、不自动重试（防重复订单）语义不变。

## 4. 统一响应外壳 `{code, msg, data}`

- 覆盖路径清单在 [app/api/response_shell.py](../app/api/response_shell.py)
  `_UNIFIED_RESPONSE_PATHS`（当前：`/orders/bill/import`、`/orders/manifest/import`、
  `/skills/tuoshu/extract`）；新接口适配只需把路径加入该集合，错误响应由全局异常
  处理器自动套壳。
- 未在清单内的路径保持旧结构 `{error: {code, message, description, details}}` 不变。
- 覆盖路径上所有场景（成功/业务失败/请求错误/限流/鉴权/503）统一三字段外壳。

## 5. 去重注册表与异步锁（重要）

[app/orders/bill/imported_registry.py](../app/orders/bill/imported_registry.py) 提供
**per-键异步锁 `alock_for()`**（`asyncio.Lock`，`async with`）：

- 临界区：查重 → submit → register；锁内 `await` 下游不阻塞事件循环；
- 去重键 = `提单号 + 箱号`（无箱号退化行序号）；同键串行保证 lookup→submit→register
  原子性与 first-write-wins；异键互不阻塞；
- 字典 setdefault 在单线程事件循环内无竞态；单进程单 worker 部署是前提。
- 注册表持久化：单文件 JSON + 临时文件原子替换（`imported_orders.json`）。
- 实例级进程内数据保护（ImportedOrderRegistry._lock，threading.Lock）仍保留。

## 6. 共享客户端单例（懒加载）

- `app/orders/http_client.py::get_async_client()`：共享 `httpx.AsyncClient`（连接池
  复用、per-request timeout）；检测到事件循环变化（测试场景）自动重建。
- `app/llm/client.py::get_async_client()`：共享 `AsyncOpenAI`；thinking / json_schema
  探测缓存与同步版共享。
- 不用 lifespan 管理：测试大量 `TestClient(app)` 不带 context manager，懒加载保证
  无 lifespan 时也可用。测试可直接 monkeypatch 这两个 `get_async_client`。

## 7. 新增接口开发清单

1. schema（`app/orders/<域>/schema.py`）→ service 编排（async，CPU 段 `to_thread`）
   → client 下游封装（`*_async`，三条第三方日志：request / response / request_error）；
2. 路由挂在 `app/api/routes/<域>.py`，经 `app.main` 接缝调用编排入口（保测试接缝）；
3. 需要统一外壳 → 路径加入 `_UNIFIED_RESPONSE_PATHS`；
4. 配置项加 `app/core/config.py` + `.env.example`（含中文注释）；
5. 测试零网络（FakeResponse / monkeypatch patch 点对齐 async 链路），提交前
   `uv run pytest -q` 全绿 + `uv run ruff check app tests` 干净。

## 8. 线程池退役说明

Phase 1-3 期间业务经 `_run_in_executor`（`ThreadPoolExecutor(skill_max_concurrency)`）
执行；Phase 4 契约统一后线程池已删除，`skill_max_concurrency` 仅作为
`_inflight_semaphore` 的并发上限继续生效（503 排队语义不变，宿主随 2026-09
结构整理迁至 `app/core/executor.py`）。历史提交（6fa3bcb / ef28a58 / 343d5db）可追溯过渡过程。
