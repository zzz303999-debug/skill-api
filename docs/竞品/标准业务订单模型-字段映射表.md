# 标准业务订单模型 · 八家族字段映射表

> 依据：37 个样本文件实测表头（2026-08-13 扫描）。
> 粒度决策：利润明细表家族（志驿/亚灏/profitStatement/赢辉）本轮**只映射业务字段**，应收/应付/车辆成本/公司成本四区块费用留给后续三类。
> 用途：作为 CanonicalOrder 数据模型与模板配置 `columns:` 段的对照基准；TMS 接口文档到位后，只需补「标准字段 → 接口字段」最后一列。

---

## 1. 标准业务订单模型（CanonicalOrder）

字段按覆盖率分三档：**核心**（≥6 家族有）、**常见**（3~5 家族有）、**扩展**（1~2 家族有）。

### 核心字段

| 标准字段 | 中文 | 类型 | 归一化规则 | 说明 |
|---|---|---|---|---|
| `bl_no` | 提单号 | str | `strip_float_tail` | 全家族覆盖；部分被 Excel 存成数字 |
| `container_no` | 箱号 | str | 大写去空格 | 全家族覆盖 |
| `box_type_qty` | 箱型（箱量） | list[Box] | `box_parse` | `箱型箱量`（40HQ*2）与 `箱型`（40HQ）两种形态统一解析 |
| `customer_name` | 客户名称 | str | 去首尾空格 | 123 为「客户简称」 |
| `work_date` | 做箱时间 | date | `month_day_with_year` | 军羽同时充当业务日期回落源 |
| `port_area` | 港区 | str | — | 秋怡缺失（其提箱点常含港区语义） |
| `pickup_point` | 提箱点 | str | — | 别名：提箱堆场/提箱场站 |
| `biz_type` | 业务类型 | str | 枚举化（进口/出口/倒箱…） | 军羽缺失；赢辉另有「进出口」列 |

### 常见字段

| 标准字段 | 中文 | 类型 | 说明 |
|---|---|---|---|
| `biz_no` | 业务编号 | str | 军羽/通寰缺失 → 归集键用 `bl_no` 兜底 |

| `customer_no` | 客户编号 | str | |

| `fleet` | 车队 | str | |
| `pieces` / `gross_weight` | 件数/毛重 | int/float | 志驿/1111 |
| `remark` | 备注 | str | 别名：应收备注/备注/大表备注 |

### 扩展字段（预留位，本轮不强制映射）

`开港时间`/`截港时间`/`进港时间`（亚灏/1111）、`船公司`（1111）、`货名`（1111）、`尺码`（1111）、`交接单时间`（1111）、`进出口`（赢辉）、`卸货工厂`/`卸货联系人`/`卸货联系电话`（1111）。

## 3. 家族缺口速查（影响 TMS 必填校验策略）

| 家族 | 关键缺口 |
|---|---|
| 军羽 | 无业务编号、无业务日期（回落做箱时间）、无船名航次、无封条号、无提箱/还箱点、无车牌 |
| 通寰 | 无业务编号、无船名航次、无封条号 |
| 秋怡 | 无港区、无司机/车牌、无封条号、无业务类型外的运输段字段 |
| 志驿/亚灏 | 业务字段最全（亚灏另有开/截/进港时间） |
| 123profit | 无船名航次、无还箱点、无客户编号 |
| 1111profit | 最全 + 独家字段（船公司/货名/尺码/回单信息） |
| 赢辉 | 无客户编号、无还箱点、无司机手机；费用以「应收合计/应付合计/成本合计」列分界（无区块表头） |

若 TMS 业务订单新增接口对「船名/航次」或「业务编号」有必填要求，军羽/通寰/123 三个家族需要业务侧确认取值策略（留空 / 默认值 / 由 TMS 生成）。

## 4. 归集策略（必填已确认，拆分策略待接口文档）

**TMS 必填项（2026-08-13 确认）：提单号 `bl_no` + 箱型 `box_type_qty`** —— 对照 §2 矩阵，8 个家族这两个字段全部原生覆盖，无缺口，不需要任何兜底取值策略；其余 TMS 字段均为选填，缺失记 missing 即可。

**接口字段已逆推确认（2026-08-13 抓包）**：提单号 = `data[N][b_order_num]`，箱型箱量 = `box[N][b_type]`+`box[N][box_num]`（数组，一票多箱型不拆单）。归集策略定案：**一单 = 一票（一个提单号）**，逐票调用；完整映射见《TMS业务订单新增接口-逆推规范》§4。

```yaml
group_key:
  primary: biz_no        # 秋怡/志驿/亚灏/profit/赢辉：同业务编号 = 同一票
  fallback: bl_no        # 军羽/通寰：无业务编号，按提单号归集
multi_row:
  # 同归集键连续多行（秋怡 6 行同 OOLU4044379500 各带一箱号）
  # → containers: [{container_no, box_type, seal_no}, ...] 聚合为数组
  # → 若接口为「一单一箱」，则拆分为多次调用（配置项 split_per_container: true）
```

## 5. 模板配置的两个补强点（相对上一版设计）

1. **列消歧**：`columns` 值支持 `列名#序号` 语法（`车牌号#2`），应对同名重复列（123profit）。
2. **费用分界方式差异化**：利润明细表家族用「区块表头」（应收/应付），赢辉用「合计列分界」（应收合计/应付合计/成本合计），军羽/通寰/秋怡用「费用列区间」——配置增加 `fee_boundary: section_header | total_columns | column_range` 三种声明，本轮只映射业务字段时用它来确定「业务列的右边界」。
